# Task 2: verified sub2api gateway adapter report

## Implementation

- Added a stable `AiGatewayPort` with structured text, image generation, image inspection, and explicit capability-test operations. Business callers receive internal values, decoded image bytes/metadata, upstream request IDs, normalized usage, and a closed safe diagnostics object; no sub2api response body escapes the adapter.
- Added a profile-driven sub2api adapter with exactly one text protocol (`SUB2API_RESPONSES`) and two image protocols (`SUB2API_RESPONSES_IMAGE_TOOL`, `SUB2API_OPENAI_IMAGES`). A selected protocol never probes or silently falls back to another protocol during a business call.
- Added stable error classification for authentication, retryable gateway statuses, invalid success bodies, timeout, cancellation, blocked redirects, missing secrets, invalid or disabled profiles, unsupported source inputs, and model mismatch. Ordinary business calls fail closed before secret lookup when a profile is disabled; only the internal administrator capability-test path can exercise a disabled candidate profile.
- Added administrator-only capability testing. It checks an authenticated models endpoint for reachability, requires the text model to satisfy the fixed `{ok:true}` JSON-schema probe, spends one source-image generation/edit request, verifies requested/returned image-model evidence, and uses `sharp` to decode the returned image rather than trusting a file signature. Only the outcome, closed feature list, latency, selected model IDs, check time, and stable error code are persisted; an exact `config_version` compare-and-swap prevents a stale result from enabling a changed profile.
- Prompts preserve the caller's exact nonblank text instead of silently truncating it. Explicit limits are 100,000 JavaScript characters and 256 KiB UTF-8; requests beyond either limit fail before secret lookup or network access.
- Structured text schemas are compiled locally with Ajv 8 in strict mode before secret lookup. Invalid/unknown schemas and remote references are rejected, and every parsed success value must satisfy required fields, types, and `additionalProperties` exactly.
- JSON, SSE, and downloaded image bodies are read through abort-aware bounded streams. Timeout and caller cancellation remain active after response headers, and readers are cancelled on timeout, cancellation, or a chunked-size violation.
- Added `AUTO_LISTING_AI_ENABLED`, which defaults off. When enabled, the runtime check requires an explicit profile reference, the exact enabled profile version, a valid environment-variable reference, and a present nonblank secret. No minimum or arbitrary API-key length policy was added.

## Verified sub2api evidence

The implementation was based only on the official `Wei-Shaw/sub2api` repository at main commit `825ca7b1fc9335f904bc077f051de815fb61e47f`, inspected on 2026-08-04:

- `backend/internal/server/routes/gateway.go` registers authenticated `POST /v1/responses`, `POST /v1/images/generations`, and `POST /v1/images/edits` endpoints.
- `backend/internal/service/openai_images_responses.go` and `openai_images_test.go` show complete image-tool results in `response.output_item.done.item.result` and `response.completed.response.output[].result`, with `type: image_generation_call`. They also show `response.image_generation_call.partial_image`; this adapter deliberately does not accept a partial image as the final asset.
- `backend/internal/service/openai_images.go` accepts JSON image edits with `images: [{image_url: "..."}]`; source bytes are therefore converted to validated local data URLs and sent to `/v1/images/edits`. Source images are never sent as the undocumented `reference_images` field on `/v1/images/generations`.
- `README.md` and `docs/ASYNC_IMAGE_TASKS.md` describe OpenAI-compatible Images responses using `data[].b64_json` or `data[].url`, and document that protocol availability depends on the deployed platform, account group permissions, and storage configuration. This is why profile protocols are explicit and must pass a real capability test.

## Security boundaries and compatibility limit

- The API key is looked up from `api_key_env_name` for every call and is never stored, returned, logged, or included in diagnostics. Secret-reader errors are converted to a stable safe code. Environment-reference names reject malformed and prototype-sensitive keys.
- Ordinary remote gateways must use HTTPS. Plain HTTP is allowed only for loopback development addresses (`localhost`, `127.0.0.1`, `[::1]`).
- Gateway endpoints and redirects must remain under the configured origin and base path. Authorization is never forwarded outside that boundary.
- `data[].url` is supported only when the URL remains under the same configured gateway origin and base path. The download sends no Authorization header, follows only bounded in-boundary redirects, enforces a byte limit, and validates the decoded image format/dimensions. This is intentionally stricter than some sub2api object-storage deployments: a profile that returns a different-origin CDN/S3 URL will fail its capability test and remain disabled. Supporting external object-storage origins later requires an explicit persisted allowlist plus DNS/IP/rebinding defenses; it is not silently permitted here.
- Caller-supplied source-image URLs are not accepted. Source images must be provided as validated bytes, capped at eight images and the configured per-image byte limit, so the adapter never performs an SSRF-prone arbitrary source fetch.
- Responses image generation explicitly selects the image tool with `action: generate` and `tool_choice`. A successful SSE stream must contain `response.completed`; any failure/incomplete/cancelled terminal event invalidates an earlier image item. The returned image model is always the configured image model, while any top-level Responses model is separately recorded as the orchestrator model.
- SSE failures are classified only from bounded machine fields (`type`, `code`, numeric status, and incomplete reason); upstream `message` is never read into an error, returned, or logged. Rate limits, server/5xx errors, timeouts, temporary failures, and all unknown `response.incomplete` events are retryable. Authentication/401/403 is a non-retryable authentication failure. Invalid-request/policy and other known non-transient failures are non-retryable. An unknown explicit `response.failed`/`error` is conservatively non-retryable because retrying a possibly cost-bearing request without transient evidence is unsafe.
- Every business response checks model evidence. A non-empty text response model must equal the requested text model. Explicit image models from Responses image items/root image fields/tools or OpenAI Images root/data items must all equal the requested image model. Mismatches return `AI_GATEWAY_MODEL_MISMATCH`; absent evidence is accepted but is explicitly marked as absent rather than being disguised as reported evidence.
- Source images have a two-stage request gate before secret lookup: a first pass sums binary `byteLength` without copying or base64 encoding (32 MiB aggregate by default), then the fully encoded JSON body is measured exactly (48 MiB by default). This still permits up to eight normal references while preventing a many-image or prompt-plus-base64 request from creating an unbounded payload.
- Logs contain only account-safe identifiers, protocol, operation, correlation/request IDs, HTTP status, and stable error code. Prompts, source image references/data URLs, image bytes, Authorization/Cookie values, and complete upstream responses are excluded.

## TDD and verification

Initial RED: both new test files failed with `ERR_MODULE_NOT_FOUND` because the adapter and profile service did not exist. Additional focused RED cases proved that oversized base64 images were initially not constrained, remote HTTP/env-name safety was missing, secret-reader errors were not normalized, fake PNG headers were not truly decoded, and whitespace secrets/prototype-sensitive environment names were not rejected.

Initial implementation GREEN was 25 adapter/profile/runtime tests. Independent review then found seven Important boundary gaps. The fix-round RED suite reproduced all seven groups, including a body-stall case that could not finish under the old reader. Final focused GREEN is 36 adapter/profile/runtime tests. The broader auto-listing suite passed 178 tests with 2 dedicated-PostgreSQL tests safely skipped before the final malformed-source input case was added. The final whole-server regression ran 820 tests: 815 passed and 5 environment-gated PostgreSQL tests skipped. App production build succeeded with the existing large-chunk warning only. Node syntax checks and `git diff --check` passed.

Independent review round 2 found three remaining Important boundaries. RED reproduced four grouped failures: unsafe SSE retry classification, text-model mismatch acceptance, image-model mismatch acceptance, and missing aggregate/request-body limits. GREEN is 40/40 focused tests. The auto-listing regression is 183 passed/2 dedicated-PostgreSQL skips; the whole `*.test.mjs` server regression ran 824 tests with 819 passed/5 configured skips; the safe integration set passed 12 with 1 explicit skip. App build, syntax, and diff checks passed. The hard-gated account-scoped migration integration remains intentionally unrun because `SONLI_MIGRATION_TEST_DATABASE_URL` is absent.

No real sub2api call was made. Therefore the actual deployment's gateway version, selected models, quota cost, and protocol compatibility remain intentionally unverified until an administrator explicitly runs the cost-bearing capability test. No dedicated PostgreSQL URL is configured, so live migration/trigger/foreign-key behavior remains gated and was not run against any ordinary or production database.

## Rollback

Set `AUTO_LISTING_AI_ENABLED=0`. The new adapter and profile service have no call site in existing business paths yet, so disabling the flag prevents future generation composition without changing current collection, listing, store, order, or extension behavior. Preserve the non-secret profile and capability evidence for audit rather than deleting it.
