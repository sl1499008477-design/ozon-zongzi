# 当前版本第二轮冗余清理执行计划

> 已由用户确认按审查建议顺序连续执行。本计划在隔离分支 `codex/second-wave-obsolete-cleanup` 上实施。

## 任务 1：建立基线

1. 复用现有未合并工作区中的依赖目录，仅在本工作区创建临时符号链接。
2. 运行当前完整验证，确认分支起点与已验证的 main 一致。
3. 记录失败、跳过项和环境限制。

## 任务 2：清理桌面端旧实现

1. 新增桌面端运行可达性测试，并先确认旧文件存在时测试失败。
2. 删除已确认不可达的五个文件。
3. 运行桌面端针对性测试和完整桌面端测试。
4. 提交一个独立变更。

## 任务 3：清理扩展端旧实现

1. 用现有行为测试保护活动利润面板、商品采集和数据面板。
2. 新增旧利润面板不可被加载的回归场景并确认先失败。
3. 删除旧利润面板和已确认零引用函数。
4. 重新扫描新增的孤立函数，逐项验证后清理。
5. 运行扩展端针对性测试和完整扩展端测试。
6. 提交一个独立变更。

## 任务 4：清理服务端零引用代码

1. 为真实模块导入和公开导出行为补充测试，先确认待删除旧导出使测试失败。
2. 删除五个生产零引用函数；只在测试可替换为当前公开入口时移除旧别名。
3. 把本地开发入口检查纳入统一验证流程并验证它实际执行。
4. 运行服务端针对性测试和完整服务端测试。
5. 提交一个独立变更。

## 任务 5：精简扩展发布包

1. 先让发布策略测试在当前含测试文件的 ZIP 上失败。
2. 修改打包和 ZIP 校验脚本，排除三个测试目录。
3. 调整解压冒烟测试，使测试夹具只在临时目录出现。
4. 重新生成扩展公共目录和 ZIP，验证源码、公用解压目录与正式 ZIP 的各自契约。
5. 停止跟踪 `app/dist` 的重复 ZIP，并通过 App 构建确认它仍会自动生成。
6. 提交一个独立变更。

## 任务 6：整理与交付

1. 将三个无引用的根目录历史截图移动到追溯材料目录，删除本地 `.DS_Store`。
2. 运行完整验证、变更范围审查和未跟踪文件审查。
3. 删除本工作区临时依赖链接和构建缓存。
4. 按用户既有选择本地合并回 main，保留 main 上的两份未提交文档。
5. 说明变更、验证、未验证范围、回滚方式和仍保留内容。
