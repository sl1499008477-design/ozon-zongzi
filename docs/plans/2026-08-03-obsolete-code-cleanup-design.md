# 当前版本第二轮冗余清理设计

## 目标

在不改变当前业务功能、接口和数据结构的前提下，删除已经无法从当前运行入口到达的旧实现，缩小浏览器扩展发布包，并移除可由构建过程重复生成的文件。

## 验收标准

- 桌面端继续使用现有模块化采集服务，旧的单文件采集实现及空占位文件不再存在。
- 浏览器扩展仍由 `jzc-calc.js` 提供利润面板，旧的内嵌利润面板和可证明零引用的局部函数不再存在。
- 服务端可证明零引用的函数不再导出或保留；专为有效测试边界存在的测试接口继续保留。
- 扩展源码目录继续保留测试，但发给用户安装的 ZIP 不再包含测试文件。
- `app/dist` 只作为构建输出，不再在 Git 中重复保存扩展 ZIP；正式来源保留在 `app/public`。
- README 正在引用的截图、数据追溯材料、服务端运行数据、现有 stash 和另一个未合并工作区全部保留。
- 全量验证通过；需要 PostgreSQL 专用测试库的项目若未配置，只能按既有条件明确跳过，不能伪装成通过。

## 方案

### 1. 桌面端旧实现

新增运行可达性测试，直接导入当前任务入口并确认它使用模块化采集服务；同时确认删除旧文件后当前入口仍能加载。删除旧的 `collection.services.js` 单文件实现、两个空类型占位文件、空文件工具和无人调用的旧下载工具。

### 2. 扩展端旧实现

通过现有扩展行为测试保护利润计算入口、商品采集和数据面板。删除未被调用的旧利润面板实现及零引用局部函数；每次删除后重新扫描引用并运行相关测试，避免误删动态入口。

### 3. 服务端零引用代码

只删除在生产代码和测试中均无调用的函数。保留承担事务边界、Excel 序列化或模块导入约束验证的测试接口，因为它们仍保护真实行为。把现有本地开发入口检查纳入统一验证流程，避免它继续成为无人执行的脚本。

### 4. 发布物

扩展源码目录仍保留测试，打包时排除 `tests`、`background/__tests__` 和 `popup/__tests__`。ZIP 检查改为验证生产运行文件齐全且测试文件不存在；打包冒烟测试从源码复制测试夹具到临时解压目录，不把测试夹具交付给用户。

### 5. 重复文件与根目录杂项

停止跟踪 `app/dist` 中由 Vite 从 `app/public` 复制出的重复 ZIP。三个未被文档引用的历史截图移动到 `source-evidence/legacy-root-screenshots`，既清理根目录又保留追溯证据。删除本地 `.DS_Store`，不处理另一个工作区的依赖缓存。

## 风险控制与回滚

- 每一类删除均先建立能在删除前失败、删除后通过的行为或发布契约测试。
- 不改变数据库、不调用真实 Ozon 写接口、不修改密钥或生产配置。
- 出现回归时可按独立提交回退对应清理，不需要回滚整批改动。
