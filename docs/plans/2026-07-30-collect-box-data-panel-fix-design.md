# 采集箱与插件数据面板修复设计

日期：2026-07-30  
状态：用户已确认采用方案 A

## 1. 业务目标

解决以下三个问题：

1. 插件提示“采集成功”后，同一 Web 账号的采集箱必须能看到商品。
2. 插件数据面板拿到 Ozon 提供的包装和市场数据后，必须显示长宽高、重量、体积和退货率；数据源确实没有提供时才保留“暂无数据”。
3. 评分保留数值和评论数量，不再输出评分后的星形 `span` 标签。

本次不改变“账号级统一采集箱，上架时再选择目标经营店铺”的既有业务规则。

## 2. 已确认的根因

### 2.1 Web 采集箱

插件采集请求已经成功写入 PostgreSQL。关系型采集记录按账号查询后，会先被转换成对外公开结构；公开结构为了避免泄露内部数据边界，正确地去掉了 `accountId`。

问题发生在后续内部兼容层：它把已经去掉 `accountId` 的公开结构放回内部状态，Web 再按 `accountId` 过滤时便把商品全部排除。

因此这是“数据存在但被错误隐藏”，不是采集失败。

### 2.2 重量、长宽高和体积

插件存在两条 Ozon 取数路线：

- 后端机群取数路线；
- 浏览器本地 Ozon 接口取数路线。

本地路线会把完整商品包中的 `weight/depth/width/height` 转换成数据面板使用的标准属性；机群路线的兼容合并只补了普通业务属性，没有可靠补齐这四个物理字段。最终数据面板虽有对应行，却只能显示“暂无数据”。

体积不单独从外部接口读取，而是由有效的长、宽、高计算得出。

### 2.3 退货率

退货率来自 Ozon 市场数据中的签收率字段，显示规则为：

`退货率 = 100% - 签收率`

现有市场数据兼容层只识别部分命名形式。需要集中兼容已有的 camelCase、PascalCase 和 snake_case 字段，但不得在数据源缺失时猜测数值。

### 2.4 评分标签

新版数据面板主动在评分数字后拼接了一个带星形图标的 `<span class="ozon-helper-rating-star">`。该标签不是业务数据，可直接从渲染结果中移除，评分数字与评论数量保持不变。

## 3. 设计方案

### 3.1 恢复 Web 内部账号边界

关系型采集列表仍继续返回安全的公开结构，不把 `accountId` 暴露给外部调用方。

内部兼容层在“已经用某个账号 ID 完成受控查询”之后，把这个可信账号 ID 重新附加到内部状态记录。随后 Web 继续按账号过滤，最后对外返回时再由公开结构清理内部字段。

这样同时满足：

- 同账号能看到自己的采集商品；
- 其他账号不能看到该商品；
- 对外 contract 不新增内部 `accountId` 字段。

### 3.2 统一插件商品包合并

提取一个可测试的纯合并逻辑，让后端机群路线和浏览器本地路线共用同一规则：

- `bundleItem.weight` → 属性 `4497`；
- `bundleItem.depth` → 属性 `9454`；
- `bundleItem.width` → 属性 `9455`；
- `bundleItem.height` → 属性 `9456`；
- 简单业务属性按属性 ID 去重合并；
- 不覆盖已经存在且有效的高优先级字段；
- 无效值、0、负数和非数字不写入；
- 完整商品包仍保留给后续上架流程使用。

数据面板继续从标准属性读取重量和尺寸，并用长宽高计算体积。采集流程与数据面板使用同一份合并结果，避免“面板看得到、采集记录却缺失”或反过来的情况。

### 3.3 统一退货率字段

市场数据标准化层集中识别以下已知字段：

- `nullableRedemptionRate`
- `NullableRedemptionRate`
- `nullable_redemption_rate`
- `redemptionRate`
- `redemption_rate`

只接受有限数值。渲染时按现有业务口径换算为退货率。字段缺失或值无效时显示“暂无数据”，不使用 0 兜底。

### 3.4 移除评分星形 span

评分渲染改为：

- 有评论数：`4.8 (123)`
- 无评论数：`4.8`

不再生成 `ozon-helper-rating-star` 标签，也不使用 CSS 隐藏来保留无用 DOM。

## 4. 影响范围

预计影响：

- `server/listing-pipeline.mjs`：内部采集状态恢复可信账号归属；
- `extension/background/service-worker.js`：统一商品包与市场字段标准化；
- `extension/content/shared-utils.js`：移除评分星形标签；
- 对应的服务端和插件自动测试；
- 插件打包产物及 Web 下载目录中的插件副本。

不涉及：

- 数据库表结构或迁移；
- Web 登录、插件 Web 登录检查；
- 经营店铺绑定或上架目标选择规则；
- 已有采集商品内容的批量重写；
- 真实 Ozon 上架、订单、库存或财务操作。

Ozon 的完整商品包接口本身可能创建草稿 bundle，这是现有取数流程已有的外部副作用。本次实现和自动测试不会新增调用次数，也不会在测试中调用真实 Ozon 接口。

## 5. Contract 与安全约束

- 采集列表查询必须继续强制要求账号范围。
- 内部附加的 `accountId` 只能用于服务端内部过滤，不进入公开 API 商品对象。
- 商品包合并必须幂等：相同数据重复合并不能产生重复属性。
- 不记录登录令牌、Cookie、数据库密码或完整敏感响应。
- 不以“前端隐藏”替代后端账号隔离。

## 6. 验收与测试

### 6.1 服务端

- 关系型采集记录恢复到内部状态后保留可信账号归属。
- 同账号的 Web 采集箱能看到商品。
- 不同账号不能看到商品。
- 公开采集商品结构仍不包含 `accountId`、`createdBy` 等内部字段。

### 6.2 插件数据

- 机群路线的完整商品包能补齐重量和三维尺寸。
- 本地路线与机群路线对相同输入产生一致的标准属性。
- 重复合并不产生重复属性。
- 非法物理数据不会覆盖有效值。
- 长宽高齐全时正确计算并显示体积。
- 市场字段的已知命名形式都能正确转换为统一签收率字段。
- 市场数据缺失时不伪造退货率。

### 6.3 展示

- 评分 DOM 中不存在 `ozon-helper-rating-star`。
- 评分数字与评论数量仍正确显示。
- 数据面板四个字段有值时显示真实值，无值时显示“暂无数据”。

### 6.4 回归

- 插件采集成功/失败提示语义不变。
- 一键跟卖、编辑上架和其他数据面板字段不受影响。
- Web 采集箱刷新、删除、编辑和上架入口做回归检查。
- 插件重新打包后，源文件与公开下载副本通过一致性校验。

## 7. 回滚方式

本次不包含数据库迁移，回滚只需撤销本次代码和插件打包提交，并重新加载上一版插件。

已写入 PostgreSQL 的采集商品不会被删除；如果回滚 Web 内部账号修复，这些商品会重新变成“数据库中存在但界面不可见”，恢复修复版本后可再次正常显示。
