## 四层复审结果

### 1. 代码结构

- 账号上下文、权限、审计、Browser Agent、同步租约、持久化事务、金额、算价、采集、上架、
  账号删除和对象清理均为独立模块。
- 新页面和共享前端逻辑已从 `App.jsx` 拆出；模块边界测试禁止入口重新膨胀。
- API 入口负责认证、路由和用例编排，核心状态机与计算逻辑可独立测试。
- 存量巨型入口仍是受控技术债，见上方第 1 项。

### 2. 业务正确

- Browser Agent 任务按账号、店铺和设备领取，写操作超时进入对账状态。
- 上架只进入 V3 幂等任务管线；单独库存直写和旧上架入口安全关闭。
- 订单与算价按最小货币单位计算，多币种分别统计。
- 算价规则必须是 `CONFIRMED` 才能校验、发布和执行；当前历史版本均为 `UNCONFIRMED`。
- 账号删除在 PostgreSQL 同一事务内清理账号、店铺、商品、订单、同步、采集和上架记录，
  审计记录保留并由外键置空。

### 3. 安全与数据

- 后端统一权限矩阵区分账号管理、算价管理、公告管理和本账号经营操作。
- 管理员进入普通业务页面时同样只读取自己的任务、采集箱和文件；跨账号操作只走专用管理接口。
- 同步、外部任务和导入具有租约、幂等键、状态版本或唯一约束。
- 关键操作写入带账号、店铺、操作人、时间和关联 ID 的审计事件，敏感字段统一脱敏。
- 配置文件不再提供可直接使用的公开密码，服务启动时校验密钥强度，端口默认只绑定本机。
- 对象存储删除失败会进入持久化重试队列，健康检查显示待清理数量。

### 4. 工程交付

- `scripts/verify.mjs` 自动发现现行测试，新测试默认进入门禁。
- PostgreSQL 迁移只新增字段或约束；正式表和 `local_state` 在一个事务内提交。
- JSON 状态通过临时文件和原子替换保存。
- 权限、状态机、幂等、金额、迁移、持久化、采集、上架、算价和账号删除均有自动测试。
- 本轮未执行真实 Ozon 写操作，也未用真实店铺做端到端回归。
