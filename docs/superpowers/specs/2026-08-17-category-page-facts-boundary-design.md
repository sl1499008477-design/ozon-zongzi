# 类目策略页面事实边界修复设计

## 目标

让已经正确打开的 Ozon 精确类目商品列表进入专用人工选样模式，同时继续阻止错误类目商品进入样本集。

## 已确认根因

Ozon 当前公开类目列表与页面脚本不再提供 Seller 侧的 `descriptionCategoryId` 和 `typeId`。扩展仍要求从这份公开列表重复提取两个字段，因此页面地址、标题和商品列表都正确时，页面事实捕获仍以 `CATEGORY_STRATEGY_SAMPLING_FACTS_INVALID` 阻断。

## 最小方案

- 页面地址仍必须是严格校验后的 Ozon 类目会话地址，且 URL 中的会话编号必须与当前会话一致。
- 页面事实中的业务范围改为使用后端签发并由扩展专用通道取得的会话范围；公开类目响应只用于生成页面响应哈希，不再承担它无法提供的 Seller 类目标识验证。
- 每个候选商品仍从 Ozon 商品数据提取 `descriptionCategoryId/typeId`，并与会话范围逐个精确比较。错误类目商品仍不能被选择或确认。
- 权限、账号隔离、会话密钥、5～20 个样本限制、人工确认和上传流程全部保持不变。

## 验收

- 公开类目响应缺少 Seller 类目标识时，正确的会话类目页不再被整页阻断。
- 商品事实缺少或不匹配精确范围时仍失败。
- 类目会话 URL 的域名、路径、查询参数和会话编号继续严格校验。
- 浏览器真实打开 `/category/nabory-skladnoy-mebeli-11504/` 后显示“取消配置”“确定选样”和商品选择按钮。
- 不选择样本、不确认、不上传。

## 回滚

回退本批次提交并恢复上一版扩展即可；不涉及数据库迁移或生产数据恢复。
