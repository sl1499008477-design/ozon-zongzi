# 自动上架规划诊断与固定骨架试验设计

## 1. 背景

当前自动上架图片规划由文字模型一次性返回完整 `ContentPlan`，包括图片数量、顺序、职责、文字密度、参考图、外观保持项、事实引用和俄语文案。模型返回通过严格 JSON Schema 后，后端还会执行商品事实和业务规则校验。

当前商品 `collect_9654f6e0fa0305c5c72e485d` 的最近一次规划请求已由 `gpt-5.4` 成功返回 HTTP 200，但业务校验统一以 `AUTO_LISTING_CONTENT_PLAN_INVALID` 拒绝。失败响应未保存，规划表和图片资产均为零，因此无法事后确定具体图片、字段或文案违反了哪条规则。

本设计先补齐规划诊断证据，再为该商品启用“配置驱动的固定骨架”试验。系统读取并冻结创建任务时的各类图片数量配置，负责稳定结构；AI 只填写俄语文案和事实引用。试验生成完成后必须停在人工审核，不自动上传 Ozon。

## 2. 已确认目标

1. 保存被业务校验拒绝的结构化规划，并记录具体错误位置和规则。
2. 使用同一冻结商品资料、策略、模型配置和校验规则进行一次文字规划受控复现，不生成图片、不调用 Ozon 写接口。
3. 为当前商品新建独立试验任务；旧失败任务和审计记录保持不变。
4. 新任务读取并冻结创建任务时填写的图片数量配置：主图固定 1 张，卖点图 2～5 张，细节图 1～2 张，场景图 1～2 张，尺寸图 0～1 张，信息图 1～2 张，总数 6～13 张。
5. AI 不能决定图片数量、顺序、职责、参考图、外观保持项或禁止声明，只能填写指定位置的俄语文案并引用已有商品事实。
6. 文案与商品事实校验通过后才允许调用图片模型；任一规划问题发生时图片调用数必须为零。
7. 配置要求的全部图片及富文本完成后进入现有 `READY_FOR_REVIEW`，等待人工审核；试验任务不得直接上传。
8. 页面提供可感知的持久化进度，不再将整个过程长期合并成“正在规划图片内容”。

## 3. 本次范围

### 3.1 包含

- 规划响应与验证结果的后台诊断证据；
- 管理员可读的安全诊断详情；
- 一次性、幂等、仅文字的受控复现入口；
- 固定骨架规划合同、AI 填充合同、合并与校验；
- 当前账号和当前采集商品的精确试验门禁；
- 新任务按冻结数量配置生成图片、富文本和进入人工审核；
- 新阶段的安全进度展示和回归测试。

### 3.2 不包含

- 自动搜索、筛选或分析 Ozon 同类目竞品；
- 新增竞品质量评分、销量或评价数据源；
- 新增类目策略管理页面；
- 将固定骨架默认开放给其他商品；
- 删除、修改或覆盖旧失败任务；
- 自动批准审核或自动上传 Ozon；
- 在普通自动化测试中调用真实 AI、Ozon 或其他付费外部服务。

现有类目策略能力仅继续提供已发布的风格和文字密度输入。当前账号已发布的 `default` v1 没有类目规则，因此本次试验使用 `BALANCED_DEFAULT`，不宣称使用了竞品分析。

## 4. 方案选择

### 4.1 采用：诊断优先，再启用服务端固定骨架

先保存原方案的真实失败证据，再将结构决定权移到服务端。固定骨架只对精确试验商品生效，其他商品继续使用原完整规划合同。

优点：

- 能回答原方案到底失败在哪里；
- 固定骨架大幅减少 AI 必须同时满足的结构规则；
- 试验范围小，可随时关闭，不影响其他商品；
- 继续复用现有任务、worker、图片生成、富文本、审核和幂等链路。

### 4.2 未采用：直接全量替换原规划器

全量替换会同时改变所有商品的生成行为，无法区分诊断修复和新规划方式的效果，回归风险过大。

### 4.3 未采用：一次性脚本直接生成配置数量的图片

脚本会绕过生产任务状态、证据、重试、对象存储、审核和权限边界，不能形成可维护的业务能力。

## 5. 总体架构

系统划分为五个职责明确的组件：

1. **规划响应记录器**：在业务校验前保存结构化 AI 响应的安全副本和哈希。
2. **规划规则诊断器**：使用闭合错误合同返回具体图片、字段和规则，不再只抛统一错误。
3. **固定骨架构建器**：根据冻结商品快照、视觉分组和任务创建时冻结的图片数量配置确定全部结构字段。
4. **AI 文案填充器**：只请求每个固定位置的俄语文案、声明类型和商品事实引用。
5. **骨架合并器**：将 AI 填充内容合并进系统骨架，再执行现有最终事实校验。

任务链路为：

```text
冻结商品资料
  → 选择并冻结规划合同
  → 系统按冻结数量配置生成固定骨架
  → AI 填写俄语文案与事实引用
  → 保存响应证据
  → 逐项诊断和最终校验
  → 生成配置要求的全部图片
  → 生成俄语富文本
  → READY_FOR_REVIEW
```

## 6. 规划合同冻结与试验门禁

- 为每个任务商品冻结规划合同：`LEGACY_FULL_PLAN_V3` 或 `FIXED_SKELETON_V1`。
- 合同必须在创建任务时写入持久化记录，worker 不得根据运行时环境临时切换。
- 服务端试验门禁使用当前账号与 `collectItemId` 的精确组合；前端不能通过隐藏字段自行选择试验模式。
- 默认值仍为 `LEGACY_FULL_PLAN_V3`。门禁关闭、账号不符、商品不符或合同缺失时不得进入固定骨架。
- 当前商品必须创建新任务才能使用 `FIXED_SKELETON_V1`；旧任务继续保留原合同和状态。
- 试验任务强制冻结为 `REVIEW` 上传模式，即使账号未来发布 `DIRECT` 策略，也不能绕过人工审核。
- 门禁配置变化不得改变已经创建的任务；回放、重试和恢复均读取持久化合同。

## 7. 配置驱动的固定骨架

任务创建时读取并冻结各职责的图片数量，合法范围沿用当前页面配置规则：

| 职责 | 合法数量 | 系统约束 |
| --- | --- | --- |
| 主图 | 固定 1 | 商品主体、参考图和外观保持项固定；默认无文案 |
| 卖点图 | 2～5 | 每张只能使用当前商品已有事实 |
| 细节图 | 1～2 | 展示材质、结构或局部细节 |
| 场景图 | 1～2 | 场景必须由当前商品事实支持 |
| 尺寸图 | 0～1 | 配置为 1 时必须存在可靠尺寸或规格证据 |
| 信息图 | 1～2 | 汇总真实功能、组成、使用方式或注意事项 |

全部职责数量之和必须为 6～13 张。当前页面示例配置为主图 1、卖点图 3、细节图 1、场景图 1、尺寸图 1、信息图 1，合计 8 张；这只是当前任务配置示例，不是系统永久固定值。

本次精确试验商品当前冻结来源只有一个视觉组，因此任务最终图片总数必须等于上述配置总数，不能再乘以视觉组数量。`FIXED_SKELETON_V1` 本轮只接受单视觉组；若该商品的新冻结来源变为多个视觉组，系统在 AI 调用前明确停止，不猜测如何拆分数量，也不产生超出页面配置的图片。

系统按“主图→卖点图→细节图→场景图→尺寸图→信息图”的稳定职责顺序，为每个重复位置生成连续且唯一的 `slotKey`。同一任务创建后，数量、顺序和职责均不可再由 AI、worker 重启或配置变化修改。

骨架构建器负责并冻结：

- `slotKey`、视觉组、职责、顺序和文字密度；
- 参考资产 ID；
- 必须保持的外观、颜色、结构、材质和配件数量；
- 每个位置可使用的事实 ID 和事实类型；
- 禁止声明集合；
- 比例、分辨率、质量和语言；
- 骨架版本和骨架哈希。

AI 无权返回或覆盖这些字段。配置要求尺寸图但当前商品缺少可靠尺寸证据时，固定骨架在调用 AI 前失败并给出明确原因，不静默减少数量、编造数据或改变为其他图片职责。

## 8. AI 填充合同

AI 使用独立的 `CONTENT_PLAN_FILL_V1` 严格结构化输出。系统根据骨架动态生成精确位置键；所有位置都必须出现，不能新增、删除、重复或改名。

每个位置只允许返回：

- `claims`：零到该文字密度允许数量的俄语文案；
- 每条文案的 `claimType`；
- 每条文案引用的 `sourceFactIds`。

动态 Schema 对事实 ID 和声明类型使用当前位置允许值的枚举，不使用当前网关不支持的 `uniqueItems`、`oneOf` 等关键字。重复引用、顺序、语义、数字和单位仍由本地校验器闭合检查。

骨架合并器从系统骨架复制全部结构字段，只把验证后的 `claims` 放入最终 `ContentPlan`。最终结果继续通过现有 `validateContentPlan`，避免固定骨架成为绕过原安全规则的旁路。

## 9. 诊断证据

下一条数据库迁移采用新增结构，不破坏现有规划表。诊断证据分为两类不可变记录：

### 9.1 规划响应

- 账号、任务、商品、规划尝试和冻结来源快照；
- 规划合同、输入哈希、骨架哈希；
- 模型、模型配置版本、提示模板版本和网关请求 ID；
- AI 结构化响应的闭合 JSON、安全大小限制和响应哈希；
- 接收时间。

响应只允许包含规划输出合同字段，不保存 API Key、凭据、完整内部提示词或供应商原始错误。

### 9.2 验证结果

- 关联的响应记录；
- 校验器版本；
- `ACCEPTED` 或 `REJECTED`；
- 一个或多个闭合问题：`code`、`slotKey`、`claimIndex`、`field`、安全期望摘要和安全实际摘要；
- 校验时间。

响应和验证结果均带账号、任务、商品复合边界，禁止跨租户读取，写入后禁止修改或直接删除；只允许随父账号清理流程级联处理。

## 10. 诊断错误合同

至少区分以下原因：

- 图片数量、角色数量、顺序或 `slotKey` 不一致；
- 文字密度或文案数量不一致；
- 参考资产不属于当前视觉组；
- 外观保持项不一致；
- 商品事实不存在、跨视觉组或不属于当前位置；
- 文案引用与声明类型不一致；
- 文案没有被所引用事实直接支持；
- 数字或单位与来源证据不一致；
- 出现认证、保修、医疗效果等禁止声明；
- 响应字段缺失、额外或格式非法。

普通任务列表只显示固定安全文案。拥有 `AI_CONTENT_MANAGE` 权限的管理员才能读取完整规划响应和逐项问题；管理员接口也必须投影闭合 DTO，不直接暴露数据库行。

## 11. 一次性受控复现

提供操作员使用的幂等诊断命令，输入必须精确绑定账号、任务、商品、冻结快照、状态版本、模型配置和幂等键。

该命令：

1. 只读加载原失败任务的冻结规划上下文；
2. 调用一次文字模型；
3. 保存规划响应和诊断结果；
4. 输出管理员诊断报告；
5. 不保存为活动 `ContentPlan`；
6. 不推进到图片生成、富文本或上传阶段；
7. 相同幂等键重放只返回同一结果，不再次调用模型。

实现完成和自动化验证通过后，执行真实文字调用前仍需进行操作时费用确认。若网关失败，不自动循环付费调用。

## 12. 进度与用户反馈

固定骨架试验使用现有持久化任务、outbox、生成尝试和图片资产派生安全进度，不使用仅存在于内存的百分比。

页面阶段至少区分：

- 正在建立固定图片结构；
- AI 正在填写俄语内容；
- 正在检查图片文案；
- 正在生成第 N／总数 张图片；
- 正在生成俄语富文本；
- 等待人工审核；
- 处理失败，并显示安全且可行动的说明。

管理员诊断详情可以查看具体规则问题；普通用户不显示原始 AI 输出、内部提示词、事实注册表、模型推理或敏感连接信息。

## 13. 失败处理与恢复

- 骨架事实不足：AI 调用数和图片调用数均为零，商品进入可诊断失败。
- AI 填充格式或业务规则失败：保存响应和问题，图片调用数为零。
- 网关超时或鉴权失败：沿用现有安全错误和有限重试；诊断复现不自动重试付费调用。
- 单张图片生成失败：沿用现有单槽位幂等重试，不重做已通过图片。
- 富文本失败：保留已通过图片并从现有恢复点重试。
- 服务重启：根据冻结规划合同、outbox、规划响应、活动计划和生成尝试恢复，不重复 AI 或图片外部调用。
- 审核前任何失败都不得创建 Ozon 上传任务。

## 14. 权限、追溯与数据安全

- 试验选择、诊断复现和诊断详情全部在后端校验账号与权限。
- 所有查询和写入包含账号、任务、商品、快照和尝试身份。
- 诊断响应有明确大小、深度、数组和字符串上限，拒绝代理、访问器、循环和危险键。
- 诊断输出不写入普通应用日志，不包含密钥或完整提示词。
- 外部文字和图片调用都使用稳定请求键；重复消息、worker 重启和响应丢失不能产生重复付费调用。
- 每次诊断、试验模式选择和人工审核均保存操作人、时间、相关 ID 和配置版本。

## 15. 测试与验收

### 15.1 纯合同测试

- 最小 6 张、当前示例 8 张和最大 13 张配置分别生成完全确定的骨架和哈希；
- 固定骨架遇到多个视觉组时在 AI 前明确失败，图片数量不会按视觉组倍增；
- 各职责数量越界、总数越界或数量字段缺失时，在 AI 和图片外部调用前安全失败；
- 相同输入重复构建结果一致；
- AI 填充不能改变数量、顺序、职责、参考图、保持项或禁止声明；
- 缺失、额外、重复位置，非法事实，跨视觉组事实，错误数字单位和禁止声明均产生精确诊断；
- 输出和诊断 DTO 递归冻结，不修改调用方输入；
- 代理、访问器、循环、危险键和超限载体在外部调用前安全失败。

### 15.2 仓储与真实 PostgreSQL 测试

- 新迁移从 001 到当前最新版本完整应用；
- 规划响应和验证结果身份、哈希、状态及复合外键闭合；
- 终态证据不可修改或直接删除；
- 跨账号、错误任务、错误商品、错误快照、错误尝试和重复请求零写；
- 幂等重放返回同一诊断结果，模型调用计数不增长。

### 15.3 组合测试

- 只有精确账号和当前采集商品的新任务冻结 `FIXED_SKELETON_V1`；
- 其他商品继续使用 `LEGACY_FULL_PLAN_V3`；
- 非法填充时文字调用一次、图片调用零次；
- 合法填充依次生成冻结配置要求的全部图片和富文本，最终为 `READY_FOR_REVIEW`；
- 审核前 Ozon 上传、库存和商品写调用均为零；
- 旧失败任务状态、版本和审计证据完全不变；
- worker 重启和消息重放不增加文字、图片或上传调用。

### 15.4 受控真实试验

自动化验证通过后分两次执行并分别确认费用：

1. 对旧任务进行一次仅文字诊断复现，输出真实逐项报告，图片和 Ozon 调用为零；
2. 为当前商品创建新固定骨架任务，按创建时提交并冻结的合法数量配置生成全部图片和富文本，停在人工审核。

不把真实 AI 结果替代自动化测试，也不调用真实 Ozon 写接口。

## 16. 影响范围

- **页面**：自动上架任务进度；管理员规划诊断详情入口。
- **接口**：管理员诊断读取与一次性诊断复现；现有任务创建响应可安全显示所冻结的规划方式。
- **数据库**：新增规划合同冻结字段和不可变诊断证据表，采用向前兼容迁移。
- **权限**：复用 `AI_CONTENT_MANAGE`；普通任务权限不扩大。
- **配置**：新增默认关闭的服务端精确试验门禁。
- **外部服务**：自动化阶段零真实调用；受控阶段一次文字诊断调用，随后最多一次完整配置规模的图片试验；Ozon 写调用为零。

## 17. 风险与缓解

- **响应证据包含商品内容**：仅后台保存闭合规划字段，限制大小，管理员权限读取，不写普通日志。
- **动态 Schema 再次被网关拒绝**：合同测试扫描不支持关键字，并通过模拟网关能力测试；真实失败后停止，不连续付费尝试。
- **固定骨架降低创意自由度**：本次目标优先保证稳定和可审核；竞品驱动的类目视觉策略后续独立设计。
- **试验门禁误作用于其他商品**：精确账号与采集商品双重匹配，并将结果冻结到任务商品。
- **未来上传策略变为直接上传**：试验任务自身冻结 `REVIEW`，不能继承后续 `DIRECT` 变更。

## 18. 回滚与恢复

- 关闭精确试验门禁后，新任务立即恢复原完整规划合同；已创建任务继续读取自己的冻结合同。
- 应用改动按独立提交回滚；新增诊断表和字段保留，避免删除审计证据。
- 受控诊断调用失败时保留失败尝试，不重复调用；修复后使用新的幂等键和明确授权重新执行。
- 固定骨架任务失败时可以取消或按现有恢复点重试；旧失败任务不受影响。
- 已生成但未审核的图片保留供查看或清理；因为没有 Ozon 写调用，不需要平台侧回滚。

## 19. 最终验收标准

1. 能针对规划失败明确显示具体图片、字段和业务规则，而非只有统一错误码。
2. 一次性受控复现只调用文字模型一次，并保存可重放的真实诊断证据。
3. 当前商品的新试验任务按创建时冻结的合法数量配置使用确定骨架，AI 无法改变数量、顺序、职责或其他结构字段。
4. 所有文案均能追溯到当前商品冻结事实；无依据内容在图片生成前被拒绝。
5. 成功路径生成冻结配置要求的全部图片和俄语富文本，最终停在人工审核。
6. 旧任务、其他商品、其他账号、现有类目策略和 Ozon 上架链路不被改变。
7. 自动化测试不调用真实 AI 或 Ozon；真实试验按费用确认分步执行并记录结果。
