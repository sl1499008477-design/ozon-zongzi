# 自动上架缺失品牌兜底设计

## 目标

自动上架商品迁移到 Ozon 当前类目后，如果当前类目把品牌属性 `85` 设为必填，而冻结的采集商品确实没有品牌，则从该类目的实时品牌字典中动态解析唯一的官方 `Нет бренда` 选项并写入任务底稿。不得写死字典值 ID，不得回写采集原始数据，也不得覆盖真实品牌。

## 已确认根因

- 采集商品 `collect_bce1e3bb59023e8d0ca6755e` 的类型 `95402` 已由 Ozon 从 description category `43434952` 迁移到 `88265327`。
- 当前类目属性接口正常返回 37 项，其中品牌 `85`、类型 `8229`、模型名称 `9048` 为必填。
- 商品保留了类型和模型名称，但品牌字段为空且没有品牌属性 `85`。
- Ozon 当前品牌字典包含官方 `Нет бренда`，本次只读诊断得到的字典值 ID 为 `126745801`。该 ID 仅是诊断证据，应用不得把它写成常量。
- 底稿准备器在严格必填属性校验中把缺少品牌折叠成 `AUTO_LISTING_CATEGORY_ATTRIBUTES_INCOMPLETE`，页面因此错误显示“类目属性暂时不可用”。

## 方案比较

### 方案 A：在目标类目底稿准备器中动态补齐（采用）

底稿准备器已经持有冻结来源、当前目标类目元数据和当前类目字典读取端口。它可以只对必填、普通、字典型品牌属性应用兜底，并把官方字典值冻结进 listing base。该方案不修改采集证据，作用域只覆盖自动上架任务准备。

### 方案 B：在通用 Ozon 导入归一化器中补齐

复用面更广，但会改变人工导入、采集编辑等入口的行为，超出本次自动上架修复范围。

### 方案 C：采集入库时写入无品牌

会改写原始采集语义，而且采集时无法知道商品未来会迁移到哪个目标类目；不采用。

## 业务规则

1. 仅当当前目标类目元数据同时满足以下条件时启用兜底：属性 ID 为 `85`、`complexId=0`、必填、存在字典 ID。
2. 每个商品变体独立判断。任何真实品牌值或已有品牌字典 ID 都必须保留，不得替换成无品牌。
3. 品牌完全缺失的变体使用候选文本 `Нет бренда` 请求当前 description category/type 的品牌字典；不得请求旧类目字典。
4. 只有实时结果中存在唯一的规范化精确 `Нет бренда` 选项时才能补齐；字典值 ID 取实时结果，不写死 `126745801`。
5. 字典接口失败、返回空、返回多个规范化精确选项或返回非法数据时失败关闭，不创建任务、不调用 AI、不创建商品、不修改库存。
6. 当前类目品牌非必填、非字典、属于复杂属性，或者品牌属性不存在时，不应用此兜底。
7. 其他必填属性缺失仍保持原有失败关闭行为，本次不猜测或自动生成其他类目属性。

## 组件与数据流

在 `auto-listing-listing-base-preparer` 内增加一个小型纯规则单元：

- 输入：当前类目元数据、按变体投影的来源属性。
- 输出：需要无品牌兜底的变体集合，或保持原样。
- 若需要兜底，品牌字典读取使用 `matchCandidates: [{ value: "Нет бренда" }]`。
- 校验唯一实时选项后，把 `{ value: 实时规范文本, dictionary_value_id: 实时 ID }` 注入缺失品牌的变体来源属性。
- 后续继续经过现有严格 normalizer、字典校验和 category rebuilder，不绕过任何必填门禁。

不得新增数据库表、迁移、外部写接口或公开 API 成功响应字段。

## 错误 contract 与页面

- 保留 `AUTO_LISTING_CATEGORY_ATTRIBUTES_INCOMPLETE` 专门表示 Ozon 类目属性读取失败或属性元数据非法。
- 新增 `AUTO_LISTING_REQUIRED_BRAND_UNRESOLVED`，HTTP 422，表示商品缺少品牌且当前类目无法唯一解析官方无品牌字典值。
- 页面固定提示：`商品缺少品牌，且 Ozon 当前类目未提供唯一的“无品牌”选项，请补全品牌后重试`。
- 错误不得包含 Ozon 原始响应、凭据、候选字典内容或内部异常。

## 测试与验收

- RED：真实 strict normalizer 路径中，两个无品牌变体缺少属性 `85` 时当前实现抛出 `AUTO_LISTING_CATEGORY_ATTRIBUTES_INCOMPLETE`。
- GREEN：同一用例只读取一次当前品牌字典，携带精确候选文本，并为两个变体注入实时返回的字典 ID。
- 真实品牌回归：已有品牌文本或字典 ID 不被覆盖，也不触发无品牌兜底候选。
- 失败关闭：零结果、重复规范结果、非法结果和字典读取失败均返回新的安全错误，且不进入任务图写入边界。
- 范围回归：底稿准备、normalizer、category rebuilder、路由、前端错误文案、自动上架服务测试通过。
- 只读现场验证：对当前采集商品运行生产底稿准备成功；不自动点击“创建生成任务”。

## 可观测性与追溯

无品牌字典值会作为 listing base 的冻结属性进入现有任务证据和哈希，不新增敏感日志。当前类目、字典版本和产品草稿版本继续使用现有版本 contract，可追溯到任务创建时的实时准备结果。

## 回滚

应用改动使用独立提交，可通过 `git revert <commit>` 回滚。没有数据库迁移和采集数据回写；回滚不会要求数据修复。已生成的任务继续使用其冻结 listing base，不受回滚影响。
