# 采集扩展登录最小重整设计

## 目标

把扩展登录收敛为一条可理解、可恢复的链路：扩展后台选择一个已登录 Web 页面，获取一次票据，服务端验证并创建会话，弹窗只展示后台的权威状态。

用户只需要点击一次“前往登录”或“重新检查”。同时打开多个 Web 页面、页面关闭、网络超时和账号失效都由扩展自动处理，不要求用户选择页面或重新打开扩展。

## 复杂度预算

- 不新增数据库表或迁移。
- 不新增通用框架、事件总线或新的持久化状态机。
- 复用现有 V2 ready/accepted、ticket exchange 和 popup 状态 contract。
- Web 页面不再承担跨页面去重职责。
- 只修改认证链路直接相关的现有模块和测试。
- 验证限定为五个关键场景、相关回归、构建和扩展包一致性检查；不运行已知会被本机 Chrome 阻塞的完整仓库验证。

## 单一职责

### 扩展后台：唯一协调者

扩展后台拥有一次认证尝试的唯一身份和执行权。它按确定顺序查找已登录的 Web 标签，只选择一个标签发送票据请求。其他标签不会收到同一轮认证请求，因此不需要跨标签共享租约。

被选标签关闭、拒绝请求或在限定时间内无响应时，后台结束该标签的尝试，再选择下一个可用标签。任何时刻最多只有一个标签和一个 ticket exchange 在执行。

### Web 页面：无状态票据适配器

Web bridge 只完成三件事：验证消息来源、调用现有票据接口、返回成功或封闭的公开失败码。它不维护全局 30 秒租约，不决定重试，不推断扩展最终登录状态。

HTTP 请求保留明确超时和取消；返回消息必须携带当前请求身份，不包含父会话、Bearer、ticket 之外的凭据或原始异常文本。ticket 只发给受信任的扩展消息链路。

### 服务端：账号和会话权威

服务端继续校验 Web 父会话、账号状态、权限、ticket 一次性和 Collector 会话。真实账号停用与账号过期返回不同稳定 code；父 Web 会话失效返回重新登录语义。

PostgreSQL 会话替换使用固定连接、显式事务和两个不含空字符的 advisory-lock key。在锁后创建新会话并撤销相同账号、相同设备的旧会话；失败必须回滚，不能误撤销旧会话。不新增表或索引。

账号停用或过期时，现有 Collector 会话必须持久撤销；账号恢复后旧 token 也不能重新生效。

### 弹窗：只读状态视图

弹窗只消费扩展后台的无凭据状态。权威 `getAuth` 未确认前显示中性“正在确认登录状态”，不提前展示旧账号主界面。账号、有效期或认证状态不匹配时，清空旧账号数据并返回登录界面。

## 数据流

1. 用户点击“前往登录”或“重新检查”。
2. 扩展后台创建一次认证尝试并查找已登录 Web 标签。
3. 后台只向第一个候选标签发送带请求身份的消息。
4. Web 页面返回 accepted，然后返回 ticket 或封闭失败码。
5. 后台收到 ticket 后只执行一次 exchange。
6. 服务端校验并原子创建 Collector 会话。
7. 后台保存无凭据认证状态；弹窗立即更新。
8. 当前标签失败时，后台结束本次子尝试，再选择下一个标签或进入可恢复错误状态。

## 失败与恢复

- 未找到已登录页面：显示“等待 Web 端登录”，不循环轰炸页面。
- 标签关闭或无响应：取消当前子尝试，选择下一个候选标签。
- 网络或本地服务暂时失败：进入有限退避；手动“立即重试”会明确开始新尝试。
- 父 Web 会话失效：显示“请先登录 Web 端”。
- 账号停用：显示“当前账号已停用”。
- 账号过期：显示“当前账号已过期”。
- 权限不足：显示“当前账号无采集权限”。
- 迟到消息：请求身份不匹配时忽略，不能取消或覆盖新的尝试。

## 最小验收范围

1. 单个已登录 Web 标签：一次请求、一次 ticket、一次 exchange，成功登录。
2. 多个已登录 Web 标签：后台只选择一个；全链路仍只有一次 ticket 和 exchange。
3. 被选标签关闭或超时：当前尝试释放，自动选择下一个标签且不重复并发。
4. 账号停用或过期：稳定中文提示，旧 Collector token 被撤销且恢复账号后不能复活。
5. PostgreSQL 相同账号和设备并发创建：最终只有一个 active session；锁键不含空字符，失败回滚。

直接相关认证测试、Web/portal policy、popup、服务端认证测试必须通过。随后重新构建 Web、重新生成 `0.13.46.4` unpacked 和 ZIP，并通过 source/UI/ZIP parity、ZIP smoke、个人数据扫描与 `git diff --check`。

## 删除与保留

删除 Web bridge 中为单页面设计的 30 秒全局租约责任，以及由它派生的 release 竞态。保留消息来源校验、请求身份校验、HTTP 超时和封闭失败码。

保留扩展后台的单一尝试身份、有限重试和无凭据状态；不再让 content flow 与 coordinator 分别拥有互相竞争的 generation。具体实现应复用一个后台生成的尝试 ID，并让所有 accepted、failure、ticket 和 exchange 消息携带该身份。

## 回滚

本次不迁移数据库。若出现问题，回退专项修复提交并重新安装修复前的 `0.13.46.4` 包即可。此前已经撤销的 Collector 会话不会自动恢复，用户可以重新登录生成新会话。
