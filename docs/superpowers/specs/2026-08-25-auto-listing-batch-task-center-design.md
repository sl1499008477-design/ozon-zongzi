# 自动上架批次顺序、价格倍率与任务中心设计

## 1. 背景

当前自动上架已经能够接收最多 100 个采集箱商品，并为同一个请求创建一个包含多个商品的任务批次，但批次中的商品会被 Worker 并行领取。页面只显示“已选择 N 个商品”和采集编号，无法确认具体商品及处理顺序；任务列表也缺少主图、总用时、进度条和按失败阶段筛选的能力。

现有价格计算使用最小货币单位和精确整数，能够保护金额正确性，但只支持“售价加减”，不能在该结果上继续应用统一的上架倍率。

本设计采用用户确认的方案 A：在现有任务、状态机、Outbox、定价和页面模块上做最小扩展。一个批次内严格逐件处理，不引入新的队列、工作流引擎或第二套任务状态。

## 2. 目标

1. 采集箱一次推送多件商品时，在页面按顺序显示商品，并按该顺序逐件处理。
2. 前一件商品进入稳定状态后才释放下一件；单件失败不阻断整个批次。
3. 在既有“售价加减”之后支持精确的“上架倍率”，默认值为 1。
4. 把任务进度从创建表单中分离为独立“任务中心”页签。
5. 任务中心展示来源商品主图、总用时、状态文字、错误原因和进度条，并支持按业务结果筛选。
6. 保持账号、店铺、仓库、金额、库存、幂等上传和外部副作用保护不变。

## 3. 非目标

- 不改变 AI 图片规划、生成、质量检查、人工审核或 Ozon 上传的业务内容。
- 不增加新的消息队列、调度服务、状态机、通用表格框架或前端状态库。
- 不改变采集箱最多推送 100 件商品的现有限制。
- 不重写历史任务配置，不重新计算历史售价，不覆盖已有业务数据。
- 不通过中文错误提示文本猜测失败类型。
- 不在本次实施中执行未经单独确认的生产数据库迁移或真实 Ozon 提交。

## 4. 批次内严格顺序处理

### 4.1 权威顺序

`auto_listing_job_items` 增加必填的 `source_order` 正整数。同一账号、同一任务批次内该值唯一，顺序从 1 开始，与创建任务请求中的商品列表顺序一致。

历史商品项按同一批次内的 `created_at, id` 确定性回填顺序。迁移只补充顺序字段、约束和索引，不修改来源快照、任务状态、商品内容或上传数据。

数据库约束负责保证：

- `source_order > 0`；
- 同一 `account_id + job_id + source_order` 唯一；
- 新建商品项必须显式写入顺序。

### 4.2 释放条件

一个商品项只有进入以下稳定状态之一，才释放同批次中的下一件商品：

- `SUCCEEDED`：已经成功上架；
- `READY_FOR_REVIEW`：生成完成，等待人工审核；
- `RETRYABLE_ERROR`：本次处理已停止，可以人工重试；
- `BLOCKED`：存在需要处理的问题；
- `CANCELLED`：已取消。

`UPLOAD_QUEUED` 和 `UPLOADING` 不是稳定状态；DIRECT 模式下必须等待前一件完成或失败后再处理下一件。这样“逐件处理”覆盖从规划到 Ozon 上传的完整流程，而不只是图片生成阶段。

### 4.3 Worker 领取门禁

继续使用现有 Outbox 和 Worker。领取待处理记录时增加同批次顺序条件：

1. 当前商品项之前不存在尚未进入稳定状态的商品项；
2. 同一批次不存在另一条正在 `PROCESSING` 的 Outbox 记录；
3. 满足条件的记录仍按已有创建时间和 ID 排序领取；
4. 不同批次、不同账号仍可并行处理。

创建任务时可以继续一次性写入整批 Outbox，不额外建设“逐件入队”服务。顺序由领取边界统一保证，避免 Controller、Service 和各 Worker 重复判断。

### 4.4 失败与人工重试

一件商品进入 `RETRYABLE_ERROR` 或 `BLOCKED` 后立即释放下一件，因此单件失败不会卡住整个批次。

人工重试会重新进入同一顺序门禁。若同批次已有另一件商品正在处理，重试记录先等待；当前处理项进入稳定状态后，按 `source_order` 重新选择最早可执行的记录。已有正在执行的商品不会被强行中断，也不会与重试商品并行运行。

## 5. 精确上架倍率

### 5.1 计算顺序

最终上架售价使用以下顺序：

`最终售价 = （现有售价规则结果 + 售价加减）× 上架倍率`

倍率默认值为 `1`，必须大于 0，最多允许 6 位小数。页面和后端不得使用二进制浮点数计算金额。

### 5.2 存储与计算

倍率以百万分之一为精度保存为整数 `price_multiplier_micros`：

- `1` 保存为 `1000000`；
- `1.25` 保存为 `1250000`；
- `0.875` 保存为 `875000`。

计算使用整数或 `BigInt`：先完成既有规则和加减，再乘以 `price_multiplier_micros`，除以 `1000000`，按最小货币单位四舍五入。最终金额仍必须为正数，并继续执行现有币种和金额范围保护。

`auto_listing_preferences` 增加默认值为 `1000000` 的倍率字段。新任务把倍率冻结进现有 `config_snapshot`，确保后续修改偏好不会改变已创建任务。

### 5.3 历史兼容

历史任务的冻结配置可能没有倍率字段。配置规范化和哈希校验必须保留这种历史结构，不回写旧 JSON，也不改变历史哈希；实际定价读取缺失倍率时按 `1` 计算。

新页面创建的任务始终显式发送倍率。定价证据增加“倍率前金额”和“倍率整数值”，最终金额字段继续表示实际提交给 Ozon 的金额。

## 6. 页面结构

自动上架页面改为两个顶层页签，不新增路由：

- **创建任务**：商品来源、上架配置和图片生成配置；
- **任务中心**：任务列表、状态筛选和刷新。

默认进入“创建任务”。创建成功后页面可切换到“任务中心”查看进度，但不改变现有 URL 中的商品来源参数。

### 6.1 采集箱商品列表

“已选择 N 个采集箱商品”的提示改为有序列表。每项显示：

- 处理顺序；
- 来源商品主图；
- 商品标题；
- SKU 或采集编号；
- 图片不可用时的占位图和采集编号。

列表顺序与 URL `ids` 参数和提交给后端的 `collectItemIds` 顺序一致。点击“创建生成任务”只创建一个批次，后端按该顺序逐件处理。

### 6.2 上架配置

“上架倍率”放在“售价加减”下方，默认显示 `1`。帮助文字明确展示计算顺序，避免用户误以为倍率只作用于原价。

上架店铺、仓库、库存、售价加减和倍率控件统一为同一输入高度。只调整当前页面样式，不修改 Ant Design 的全局主题。

## 7. 任务中心

### 7.1 商品列

商品列显示不可变来源快照中的第一张图片，图片下方保留简短采集编号用于追踪。后端只投影页面需要的主图、标题和 SKU，不把完整来源快照暴露给前端。

历史快照没有图片或图片加载失败时显示占位图，不阻断任务列表。

### 7.2 任务用时

任务用时从用户点击“创建生成任务”产生的批次 `created_at` 开始计算，包含批次排队等待时间：

- 处理中：显示实时累计用时；
- `SUCCEEDED`：使用成功状态的 `updated_at` 固定显示“总用时”；
- 失败、阻断或取消：使用该状态的 `updated_at` 显示“未上架 · 已用时”；
- `READY_FOR_REVIEW`：继续实时累计，因为完整上架流程尚未结束。

这样后续顺序商品的用时包含等待前序商品的时间，符合“从创建任务到成功上架”的定义。

### 7.3 进度条

任务进度列组合显示：

- 当前业务状态；
- 可理解的错误原因；
- 进度条；
- 必要时的恢复或重试入口。

进度百分比由现有状态机和已有 `workflowProgress` 派生，不保存第二个进度状态。基础映射为：

| 状态 | 进度 |
| --- | ---: |
| `CREATED` | 5% |
| `SOURCE_READY` | 15% |
| `PLANNING` | 30% |
| `GENERATING` | 60% |
| `READY_FOR_REVIEW` | 80% |
| `UPLOAD_QUEUED` | 85% |
| `UPLOADING` | 95% |
| `SUCCEEDED` | 100% |

`workflowProgress` 有更细阶段时在对应区间内细化。`RETRYABLE_ERROR`、`BLOCKED` 和 `CANCELLED` 保留失败前已达到的阶段进度，并使用错误或中性色，不伪装成完成。

### 7.4 状态筛选

任务中心提供以下筛选项：

- 全部；
- 处理中；
- 等待审核；
- 生成失败；
- 上架失败；
- 上架成功；
- 已取消。

“生成失败”和“上架失败”由后端基于现有状态、恢复阶段和错误码投影稳定的 `failureStage`，取值为 `PREPARATION`、`GENERATION` 或 `UPLOAD`。前端只按该字段分类，不解析中文错误文本。

## 8. 公开数据 contract

现有任务列表 DTO 最小增加：

- `sourceOrder`；
- `sourceThumbnailUrl`；
- `sourceTitle`；
- `sourceSku`；
- `jobCreatedAt`；
- `failureStage`。

继续保留已有 `createdAt`、`updatedAt`、`status`、`statusVersion`、`workflowProgress`、店铺、仓库和错误信息字段。所有查询继续按 `account_id` 过滤，并通过已有账号范围的任务和来源快照关联获得数据。

倍率配置新增可选的 `priceMultiplierMicros`。历史 contract 缺失该字段时含义为 `1000000`；新请求必须显式包含该字段。

## 9. 数据流

1. 页面按 URL 顺序读取最多 100 个采集箱商品，并展示有序来源列表。
2. 用户配置店铺、仓库、库存、售价加减、上架倍率和图片参数。
3. 页面把有序 `collectItemIds` 和配置一次性提交给现有创建任务接口。
4. 后端在一个事务中创建任务、来源快照引用、带 `source_order` 的商品项和 Outbox。
5. Worker 领取边界只允许当前批次最早的非稳定商品处理。
6. 该商品进入稳定状态后，下一件自动获得处理资格。
7. 任务中心从现有任务列表接口读取商品投影、状态、阶段和时间，纯函数派生进度、用时和筛选分组。
8. Ozon 上传继续使用现有幂等键、账号、店铺、仓库、库存和 DIRECT/人工审核策略。

## 10. 错误处理

- 某个来源商品在创建前不存在或不属于当前账号：沿用现有创建边界拒绝该请求，不创建部分批次。
- 历史任务缺少倍率：按倍率 1 读取，不报错、不修改历史数据。
- 历史来源图片缺失：显示占位图，不影响任务读取或重试。
- Worker 暂时失败：沿用现有可恢复错误；商品进入稳定失败状态后释放下一件。
- 人工重试与同批次正在处理项冲突：保留重试请求，等当前执行项稳定后再领取。
- Ozon 拒绝或上传失败：仍由现有提交对账、幂等和重试边界处理，只把失败阶段投影给页面。
- 倍率导致最终金额超出存储或平台允许范围：在权威定价边界阻断，不截断、不回退浮点数。

## 11. 预计修改边界

实施只修改现有职责相关模块：

- 数据库迁移：商品项顺序、偏好倍率、约束和索引；
- 自动上架 contract 与定价模块：倍率解析、精确计算和历史兼容；
- 自动上架任务创建与 PostgreSQL 仓储：保存顺序、任务列表投影；
- AI Outbox 领取仓储：批次顺序门禁；
- 自动上架路由和视图投影：安全返回主图、阶段和批次时间；
- `AutoListingPage`、现有配置和视图纯函数：双页签、商品列表、倍率、任务中心、进度和筛选；
- 当前页面 CSS：控件高度、缩略图、进度和窄屏布局；
- 与上述行为直接相关的已有测试。

如果实施时发现字段已由更专一的现有文件负责，应落到该文件，不建立平行 Service、Manager 或 Mapper。

## 12. 测试与验收

### 12.1 数据库和顺序

- 新批次按请求顺序保存连续的 `source_order`。
- 历史任务确定性回填且不改变原业务字段。
- 同一批次不能保存重复或非正顺序。
- 同一批次最多只有一个 Outbox 处于实际处理状态。
- 前一件 `SUCCEEDED`、`READY_FOR_REVIEW`、`RETRYABLE_ERROR`、`BLOCKED` 或 `CANCELLED` 后释放下一件。
- 前一件 `UPLOAD_QUEUED` 或 `UPLOADING` 时不释放下一件。
- 人工重试不会与同批次正在运行的商品并行。
- 不同批次仍可并行。

### 12.2 金额

- 倍率 1 保持当前价格结果不变。
- 正数、小数和 6 位小数倍率按最小货币单位精确四舍五入。
- 非正数、超过 6 位小数和最终金额越界在后端权威边界拒绝。
- 历史无倍率配置仍能通过哈希校验并按 1 计算。
- 偏好保存、读取和新任务冻结配置保持一致。

### 12.3 页面

- 多个采集箱商品按 URL 和提交顺序显示主图、标题及编号。
- 店铺、仓库、库存、售价加减和倍率控件高度一致。
- 任务中心可独立切换和刷新。
- 商品主图不可用时显示占位图。
- 处理中用时会更新，成功用时固定，失败明确标注“未上架”。
- 所有状态和细分阶段映射到正确进度，不出现失败任务 100% 的误导。
- 各筛选项使用 `failureStage` 和状态正确归类。
- 窄屏下列表和配置不重叠，必要时允许表格横向滚动。

### 12.4 代表性端到端验证

使用代表性已有数据库数据验证：

1. 至少包含两个商品的批次，确认逐件领取和失败后放行；
2. 一个历史无倍率任务，确认可读取且价格不变；
3. 一个新倍率任务，在不触发真实 Ozon 写入的安全模式下验证冻结配置和最终金额；
4. 一个成功、一个生成失败、一个上架失败和一个等待审核任务，验证任务中心展示与筛选；
5. 浏览器真实跑通“打开多商品推送 URL → 确认有序列表 → 创建任务 → 查看任务中心进度”。

真实 Ozon 上传和生产数据库迁移属于外部副作用，实施前按现有规则单独说明；没有执行时必须在交付中明确标记为未验证，不能宣称完全上架成功。

## 13. 回滚与恢复

- 页面、contract、定价和领取逻辑按独立小批次提交，可分别回滚。
- 新数据库字段为附加字段；回滚应用代码时保留字段不会影响旧代码。
- 不在回滚时删除顺序或倍率数据，不执行破坏性降级迁移。
- 倍率默认 1，关闭新页面入口后不会改变现有价格行为。
- 顺序门禁异常时先停止相关 Worker、回滚该批次代码并调查，不在运行中的失败逻辑上继续叠加补丁。
