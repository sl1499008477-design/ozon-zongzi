# sub2API OAuth 图片工具选择兼容设计

## 目标

让自动上架能力测试在现有 sub2API `0.1.173`、OpenAI OAuth 账号和 Responses 图片工具链下，使用网关可接受的工具选择格式完成图片生成请求，同时保持文字模型、图片模型、租户边界、付费确认和审计记录不变。

## 已确认根因

当前 Ozon 适配器向 `/v1/responses` 发送 `tool_choice: { type: "image_generation" }`。sub2API 正确转发了请求，但 OAuth 上游以 HTTP 400 拒绝该显式选择；sub2API 将其包装为 HTTP 502，Ozon 因而稳定显示 `RETRYABLE_GATEWAY`。同一请求中的连接检查和文字生成均成功，失败仅发生在图片阶段。

## 方案

只修改 `SUB2API_RESPONSES_IMAGE_TOOL` 请求构造：

- 保留 `tools` 中的 `image_generation` 工具以及已冻结的图片模型。
- 将 `tool_choice` 改为字符串 `"auto"`，与 sub2API OAuth 兼容桥的正式实现一致。
- 保留明确的图片生成输入；如果上游没有返回最终图片，现有解析器继续失败关闭，不得把文字响应误判为图片成功。
- 不启用全局 `force_codex_cli` 或全局图片桥，避免影响其他 sub2API 客户端。
- 不更改已有配置或能力测试记录；管理员保存新配置并明确确认费用后，才能再次发起真实能力测试。

## 稳定合同与安全边界

- API 路径仍为 `/v1/responses`。
- 文字协议仍为 `SUB2API_RESPONSES`，图片协议仍为 `SUB2API_RESPONSES_IMAGE_TOOL`。
- Key 解析、租户、连接版本、能力测试租约、幂等请求键和三阶段付费预约合同不变。
- 日志和测试不得包含 Key、提示词、图片数据或原始上游响应。

## 测试与验收

1. 先修改适配器单元测试，使其要求 `tool_choice === "auto"`，并观察现有实现产生精确 RED。
2. 最小修改生产请求构造后，专项测试转为 GREEN。
3. 回归 Responses 图片 SSE 最终结果、失败事件、能力测试三阶段、设置页面合同和设置路由。
4. 运行前端生产构建和服务健康检查。
5. 不自动执行真实 AI 调用；最终真实能力测试由管理员在页面确认费用后手动执行。

## 回滚

代码异常时回滚本次适配器提交即可。数据库没有迁移或数据重写；历史测试证据保持不可变。
