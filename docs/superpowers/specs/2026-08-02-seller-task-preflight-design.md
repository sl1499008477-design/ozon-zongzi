# Seller 待处理任务预检设计

## 目标

修复浏览器扩展在没有待处理 Ozon 补全任务时，仍按分钟反复打开、加载并关闭 Seller 辅助页面的问题。

验收标准：

- 账号没有当前可领取的补全任务时，后台定时检查不得创建、刷新、聚焦或关闭 Seller 页面。
- 账号存在当前可领取的补全任务时，扩展继续使用现有 Seller 上下文恢复和只读采集流程。
- 新检查只能返回布尔值，不返回任务数量、SKU、商品内容、Seller 公司标识或其他账号数据。
- 检查失败时关闭采集流程，不打开 Seller 页面；后续定时检查或新采集事件仍可恢复。
- 账号、Collector 会话和权限边界继续由后端验证。

## 根因

后台 `drainAvailable` 在调用领取任务接口前先获取 Seller 上下文。获取上下文可能创建隐藏 Seller 辅助页；空队列返回后租约立即释放，辅助页随即关闭。每分钟的定时检查重复该顺序，因此形成打开、加载、关闭循环。

## 方案

增加一个固定的 Collector 只读预检接口。接口使用当前 Collector 账号和会话，在后端判断是否存在当前时间可领取的任务，只返回 `{ ok: true, available: boolean }`。

扩展后台流程调整为：

1. 建立或复用 Collector 操作会话。
2. 调用待处理任务预检。
3. `available=false` 时直接结束本轮，不读取或恢复 Seller 上下文。
4. `available=true` 时才执行现有 Seller 上下文恢复、领取、采集和提交流程。

该预检只提供提示，不领取任务，也不改变任务状态。预检后任务被其他执行器领取属于允许的并发情况；本轮领取返回空即可，后续定时检查继续工作。

## 后端边界

- 路由使用固定路径和 `collector.ozon.read` 权限，不接受查询参数、账号、店铺或 Seller 控制字段。
- Service 只返回布尔结果。
- Repository 在 JSON 与 PostgreSQL 两种实现中使用相同的可领取条件：账号一致、会话有效、任务未终止、截止时间未过、重试时间已到，并遵守首选会话的一秒保护期与账号并发上限。
- 查询不写缓存、不领取任务、不更新 Seller watermark，不产生平台副作用。

## 失败处理

- 鉴权、网络或服务端检查失败：本轮后台 drain 失败关闭，不打开 Seller 页面，也不循环重试；等待下一次明确 kick。
- 预检为真但领取时已无任务：正常结束并释放 Seller 辅助页。
- 任务在预检后新增：由上传事件的 kick 或下一分钟定时检查处理。

## 测试与交付

- 扩展行为测试先复现“空队列仍读取 Seller 上下文”，再验证修复后 Seller 恢复调用次数为零。
- 路由、Service、JSON Repository、PostgreSQL SQL contract 覆盖账号/会话隔离、到期任务、未来重试任务和并发上限。
- 回归现有领取、失败重试、Seller 切换围栏和只读采集测试。
- 重新构建 Web、重新打包 `0.13.46.2` 扩展，并校验源码、公开解包目录和两份 ZIP 一致。

## 回滚

回滚本次提交即可恢复原领取顺序；不新增数据库字段或破坏性迁移。若新预检不可用，扩展会安全停止本轮后台采集，不会打开 Seller 页面或写入错误结果。
