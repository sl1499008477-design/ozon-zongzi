# 「ozon 粽子」品牌与插件数据面板视觉还原设计

## 1. 背景与目标

当前产品在 Web、浏览器扩展弹窗和 Ozon 页面注入组件中使用 `sonli` 名称与旧图标。用户已经提供一组「ozon 粽子」品牌 SVG 资产，并指定以下原型作为浏览器扩展数据面板的视觉依据：

- 原型地址：`https://ozon-operations-prototype.sl1499008477.chatgpt.site/#/plugin`
- 原型主状态：商品页右侧「OZON 选品助手」数据面板
- 原型设置状态：点击数据面板右上角齿轮后出现的「插件展示设置」弹窗

本次目标是：

1. 将用户可见的产品 Logo 和产品名称统一替换为「ozon 粽子」。
2. 按原型还原浏览器扩展注入到 Ozon 页面中的数据面板和字段设置弹窗样式。
3. 保留现有真实字段、数据来源、交互逻辑和持久化行为，不新增原型中的模拟业务字段。
4. 保持现有账号、采集、算价、权限、数据边界和外部调用不受影响。

## 2. 已确认方案

采用方案 A：保留功能与数据 contract，只重构用户可见品牌层和数据面板表现层。

不采用以下方案：

- 不复制原型中的 35 项模拟字段，因为当前系统并不具备所有字段的可靠数据来源。
- 不只覆盖颜色和圆角，因为现有结构与原型在标题区、指标区、分组区和设置弹窗层级上存在明显差异。
- 不重写数据请求与业务逻辑，因为本次目标是视觉还原，不是数据链路改造。

## 3. 范围

### 3.1 品牌替换范围

用户可见品牌统一为：

- 产品名称：`ozon 粽子`
- 数据面板标题：`ozon 粽子 · 选品助手`
- 品牌蓝：`#1268FF`
- 深海军蓝：`#10234A`

使用用户提供的现有资产，不重新绘制 Logo：

- 标准浅色界面横版：`ozon-zongzi-logo-primary.svg`
- 深色界面横版：`ozon-zongzi-logo-dark.svg`
- 反白版：`ozon-zongzi-logo-white.svg`
- 单色版：`ozon-zongzi-logo-mono.svg`
- 小尺寸图形：`ozon-zongzi-symbol.svg`

品牌替换覆盖：

- Web 页面标题、登录页、侧边栏品牌区、数据大屏品牌区和插件下载页。
- 浏览器扩展 manifest 名称、描述、工具提示、扩展弹窗标题和品牌区。
- Ozon 页面中由扩展注入的数据面板、算价区和其他用户可见品牌文案。
- Chrome 扩展的 16、48、128 像素图标及 Web 对应图标。

以下内部标识保持不变，以兼容现有数据和调用方：

- 环境变量名，例如 `SONLI_ADMIN_PASSWORD`。
- 本地存储键、协议常量和消息类型，例如 `SONLI_COLLECTOR_AUTH`。
- 数据库锁名、迁移标识、历史字段名和内部 CSS 类名。
- 当前扩展下载路径与历史兼容路径，除非仅修改页面上的显示文案。

### 3.2 数据面板范围

数据面板继续使用现有渲染和灌数 contract：

- `jzRenderProductPanelV2`
- `jzPopulatePanelV2`
- 当前字段显隐存储
- 当前月/周统计周期
- 当前采集、算价、跟卖和其他动作

视觉重构覆盖：

- 品牌标题区
- 数据更新状态
- 齿轮设置按钮
- 顶部核心指标
- 业务字段分组
- 无数据、加载、错误和锁定状态
- 底部操作区
- 全局提示和必要的窄宽度适配

### 3.3 设置弹窗范围

设置弹窗按原型还原以下结构：

- 半透明页面遮罩
- 居中的大尺寸白色弹窗
- 标题、说明和关闭按钮
- 当前已展示数量
- 全部开启、全部隐藏
- 按现有真实字段组织的分组卡片
- 每组全选或全不选
- 字段复选项
- 统计周期控制
- 恢复默认和完成设置

字段数量必须根据当前真实字段动态计算，不固定显示原型中的 `35 / 35`。

## 4. 视觉设计

### 4.1 数据面板

数据面板匹配原型的轻量、清晰、低噪声样式：

- 白色背景，浅蓝灰边框，约 14–16 像素圆角。
- 标题区不使用整块蓝色渐变，改为白底。
- 左侧使用蓝色方形品牌图形，旁边展示产品名和绿色数据状态。
- 右侧齿轮为独立浅边框按钮，具有悬停、键盘聚焦和按下状态。
- 顶部指标采用浅蓝背景卡片；在较宽侧栏中为四列，在窄侧栏中自动变为两列。
- 业务分组使用浅色标题、图标和规整的双列键值布局。
- 数字使用等宽数字特性，但不强制依赖未安装字体。
- 空值继续明确显示「暂无数据」，不伪造数据。
- 加载、错误、会员锁定和采集成功状态沿用现有语义，只调整到同一视觉语言。

### 4.2 设置弹窗

- 遮罩层覆盖 Ozon 页面并使用高层级，避免被宿主页面遮挡。
- 弹窗宽度随视口变化，桌面端约占可视宽度的 70%–80%，同时设置合理最大宽度。
- 标题区、概览区、分组区和底部操作区有清晰层级。
- 分组区使用响应式网格；空间不足时从三列降为两列或一列。
- 复选项保留原生可访问语义，并提供可见的勾选、悬停和聚焦状态。
- 「完成设置」为品牌蓝主按钮，「恢复默认」为次按钮。
- 保存后继续通过现有存储和页面刷新机制生效。

### 4.3 品牌资产适配

- Web 页面直接使用 SVG，避免缩放模糊。
- Chrome 扩展图标由提供的 symbol SVG 生成透明背景 PNG。
- 图标周围保留品牌规范要求的安全留白。
- 不将横版 Logo 强行裁成方形图标。
- 不使用文字、emoji、CSS 图形或重新手绘 SVG 代替提供的品牌资产。

## 5. 结构与职责

### 5.1 品牌配置

新增或收敛一个稳定的品牌展示 contract，至少包含：

- `displayName`
- `productName`
- `primaryColor`
- `logoUrl`
- `symbolUrl`

Web 和扩展各自从其已有运行环境读取该 contract。品牌展示配置只负责用户可见内容，不接管账号、权限或数据逻辑。

### 5.2 面板渲染

共享渲染器继续负责：

- 生成面板结构
- 根据字段定义生成真实分组
- 提供 `data-field` 定位 contract
- 支持异步灌数和显隐更新

数据请求与数值计算继续由现有函数负责，避免视觉代码直接依赖后端响应结构。

### 5.3 设置状态

设置弹窗继续使用现有字段显隐数据结构。新增的“全部开启、全部隐藏、分组控制、恢复默认”只是同一设置 contract 的操作入口，不创建第二份状态。

## 6. 数据流与兼容

数据流保持：

1. 现有扩展代码读取 Ozon 页面和后端数据。
2. 现有合并逻辑生成面板数据。
3. 共享面板渲染器输出原型风格 DOM。
4. 异步灌数函数按 `data-field` 更新数值。
5. 设置弹窗更新现有字段显隐配置。
6. 所有已渲染面板应用同一配置。

兼容要求：

- 已保存的字段显隐配置继续生效。
- 已保存的月/周统计周期继续生效。
- 旧账号、店铺、采集箱、扩展会话和本地缓存不迁移、不清空。
- 扩展升级后不要求用户重新登录。
- 品牌替换不得改变账号边界、店铺边界或采集归属。

## 7. 异常与边界

- Logo 加载失败时保留可读的产品名称，不显示破损占位图。
- 某项数据不存在时显示「暂无数据」，不显示 `undefined`、`NaN` 或错误单位。
- 设置存储失败时不关闭弹窗，并向用户显示失败提示。
- 原型布局在 Ozon 侧栏过窄时允许响应式降列，不允许横向溢出页面。
- 宿主页面样式不得污染插件组件；插件 CSS 选择器保持命名空间隔离。
- 弹窗关闭、遮罩点击和键盘聚焦行为必须可用。

## 8. 测试与验收

### 8.1 自动化验证

- 品牌展示测试：Web 与扩展用户可见名称为「ozon 粽子」。
- manifest 测试：扩展名称、描述、标题和图标路径有效。
- 资产测试：所有 SVG/PNG 存在，图标尺寸和透明背景符合要求。
- 面板渲染测试：标题区、状态、齿轮、指标区、真实字段分组和操作区存在。
- 设置测试：动态总数、全部开启、全部隐藏、分组选择、恢复默认和保存可用。
- 持久化测试：刷新后字段显隐和统计周期保持。
- 回归测试：灌数、空值、采集、算价、登录和账号隔离 contract 不变。
- 扩展打包测试：源码目录、公开目录和 ZIP 内容一致。

### 8.2 视觉验收

使用相同视口和相同交互状态进行截图对比：

- 原型数据面板 vs. 本地扩展数据面板。
- 原型设置弹窗 vs. 本地设置弹窗。

必须重点检查：

- 卡片宽度与圆角
- 标题区层级
- Logo 清晰度与留白
- 指标卡间距
- 分组栅格
- 字体大小与字重
- 边框、按钮和遮罩
- 窄侧栏响应式表现

P0、P1、P2 视觉问题全部修复后才算通过；P3 轻微差异可以记录为后续优化。

## 9. 影响与非影响范围

预计影响：

- Web 品牌展示组件和静态资产
- 扩展 manifest、弹窗和品牌运行配置
- 共享数据面板渲染与设置弹窗
- 数据面板 CSS
- 扩展测试与打包产物

明确不影响：

- 数据库结构与已有数据
- 后端 API contract
- 权限和账号隔离
- 同步与采集链路
- 外部平台调用
- 订单、库存、金额、汇率和结算逻辑

## 10. 回滚与恢复

- 品牌资产与展示代码可通过回滚本次提交恢复旧 Logo 和名称。
- 面板结构和 CSS 可独立回滚，不需要恢复数据库或清理用户数据。
- 字段显隐继续使用旧存储 contract，因此回滚后已有设置仍可读取。
- 若新版扩展包异常，可重新发布上一版扩展目录和 ZIP。

## 11. 完成标准

同时满足以下条件才可交付：

1. Web 与扩展所有主要用户可见品牌统一为「ozon 粽子」。
2. Chrome 扩展图标和页面 Logo 使用用户提供的真实品牌资产。
3. 数据面板和设置弹窗在视觉上通过原型对比。
4. 原型中的模拟字段未进入生产逻辑。
5. 当前真实字段、显隐设置、统计周期和操作行为保持可用。
6. 完整自动化验证通过。
7. 明确记录未验证范围、回归风险和回滚方式。
