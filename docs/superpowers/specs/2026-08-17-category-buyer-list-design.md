# 类目策略打开 Ozon 买家类目列表设计

## 目标

类目策略启动选样时，应打开锚定商品实际所属的 Ozon 买家端末级类目商品列表，而不是把 Seller `descriptionCategoryId` 当成网页类目编号。选样完成后仍停在人工审核，不改变上传行为。

## 已确认根因

- Seller 类目编号和 Ozon 买家网页类目编号不是同一套编号。
- 当前采集记录只保存商品 URL 和 Seller 类目证据，没有保存商品页可见面包屑中的买家末级类目 URL。
- 类目策略服务当前拼接 `/category/<descriptionCategoryId>/`，因此生成了错误网址。
- Web 与扩展交接白名单只接受上述纯数字类目路径，反而拒绝真实的 `/category/<slug>-<id>/` 路径。

## 最小方案

1. 扩展在 Ozon 商品页从可见面包屑中选择最后一个单层类目链接，规范化为 `https://www.ozon.ru/category/<slug>-<id>/`。
2. 新采集商品把该链接写入现有采集 payload 的 `buyerCategoryUrl`，由现有 JSON 草稿持久化；不新增表、不做数据迁移。
3. 类目策略读取草稿时优先使用 `buyerCategoryUrl`，没有该字段的历史记录继续使用锚定商品 URL。
4. 服务端只给已验证的真实类目 URL或锚定商品 URL添加选样会话参数，不再从 Seller 类目编号生成网页 URL。
5. 历史记录打开锚定商品页后，商品页内容脚本读取同一可见面包屑，立即跳到末级类目列表并保留选样会话参数。
6. Web 和扩展只接受 `www.ozon.ru` 下的单层真实类目路径或带数字 SKU 的商品路径，并且只允许一个 `zongziCategoryStrategySession` 查询参数。

## 安全和兼容边界

- 不调用 Seller 写接口，不修改 Ozon 商品，不触发上传。
- 不改变账号权限、多租户隔离、会话密钥保护或人工审核流程。
- 不信任服务端返回的任意 URL；Web、扩展后台和商品页跳转各自在自己的边界重新投影允许的路径。
- 面包屑无法解析时停止跳转并显示现有失败状态，不猜测类目编号。
- 当前历史商品可通过商品页回退路径立即使用；重新采集后的商品直接打开类目列表，少一次中转。

## 验收

- 锚定商品 `1941181573` 最终打开 `/category/nabory-skladnoy-mebeli-11504/`，并携带选样会话参数。
- 错误的 `/category/17029005/` 不再由服务端生成。
- 恶意域名、额外查询参数、品牌二级路径和非商品/非类目路径仍被拒绝。
- 采集、类目策略启动、扩展选样、人工审核相关测试通过；代表性真实流程能到达正确类目列表。
