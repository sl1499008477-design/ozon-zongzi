# Sonli Ozon 原型样式统一改造设计

> **历史文档：** 本设计保留当时的业务背景、授权和方案时态；当前实现与验证结果以已提交代码、可复现测试和最终保护性基线报告为准。

- 视觉参考源码：`<approved-prototype>`
- 视觉参考地址：`http://localhost:5173/`

## 1. 目标

将目标项目全部现有页面统一调整为参考原型的蓝白圆角运营台风格，同时完整保留现有路由、数据来源、接口调用、权限约束、状态流转和业务交互。

本次改造解决以下问题：

- 当前页面与参考原型在背景、侧栏、顶部操作区、卡片、表格、表单和字体层级上不一致。
- 页面间视觉规则不统一，部分页面仍使用偏硬的分割线、密集边框和不同圆角。
- 当前移动端样式与目标视觉语言不一致。
- 参考原型在约 1280px 宽度下存在横向裁切，本次改造不得复制该缺陷。

## 2. 用户结果

改造完成后，用户在登录、首页、商品、订单、利润、采集上架、AI、促销、消息、店铺、账号、算价、插件和数据大屏等现有页面中，应感受到一致的 Sonli/Ozon 运营台视觉体系。业务数据和操作结果必须与改造前一致。

## 3. 已选方案

采用“设计系统统一换肤 + 重点页面精调”。

先将参考原型的视觉规则固化为全局设计令牌和 Ant Design 主题，再统一应用到应用外壳及公共组件。仪表盘、商品列表、订单列表、利润页、店铺配置、算价配置等复杂页面进行针对性精调。

不采用以下方案：

- 不逐页建立互不关联的独立样式体系，以免重复 CSS 和后续漂移。
- 不用原型代码重写现有前端，以免破坏当前业务逻辑和接口绑定。

## 4. 视觉设计系统

### 4.1 核心令牌

- 页面背景：`#F6FAFE`
- 主表面：`#FFFFFF`
- 次级表面：`#F7FAFE`
- 主色：`#005AF8`
- 主色悬停：`#004FE0`
- 主色浅底：`#EEF5FF`
- 主文字：`#071737`
- 次级文字：`#65718A`
- 弱文字：`#8C98AC`
- 普通边框：`#DCE8F7`
- 强边框：`#CBDCF2`
- 成功色：`#14994A`
- 警告色：`#B76708`
- 危险色：`#D93632`
- 紫色辅助：`#6C4DE6`
- 阴影：以低透明度蓝灰阴影为主，避免深灰重阴影

### 4.2 形态规则

- 普通输入、按钮和小控件：9–14px 圆角
- 卡片、工具栏和信息面板：16–18px 圆角
- 主侧栏和大型聚合面板：24–26px 圆角
- 状态标签：胶囊形圆角
- 重要操作使用实心蓝色；次要操作使用白底、浅蓝边框
- 不使用新建 CSS 图标、字符图标或手绘 SVG；继续使用现有 Ant Design 图标

### 4.3 字体层级

- 字体栈：`Inter`、`PingFang SC`、`Microsoft YaHei`、`Noto Sans CJK SC`、系统无衬线字体
- 页面眉题：大写英文、小字号、蓝色、增加字距
- 页面主标题：深蓝黑、高字重
- 页面说明：次级灰蓝色
- 指标数字：高字重，优先保证金额、比例和数量的扫描效率

## 5. 应用外壳

### 5.1 左侧导航

- 桌面端使用悬浮白色圆角侧栏。
- 品牌区、导航区、插件入口和运行状态区保持清晰分组。
- 选中项使用浅蓝渐变背景、蓝色图标块和右侧状态点。
- 保留全部现有菜单、路由、展开状态和点击行为。

### 5.2 顶部操作区

- 汇率、当前店铺、同步、通知和账户入口调整为参考原型的轻量浮动控件。
- 不修改店铺切换、同步、通知和账户菜单的业务行为。
- 小屏幕只保留必要入口，其余内容通过现有菜单或紧凑状态呈现。

### 5.3 页面标题

- 页面统一使用“英文眉题 + 中文主标题 + 说明文字 + 页面操作”的结构。
- 不替换当前业务文案；仅在已有信息足够时补充视觉眉题。
- 页面操作在桌面端靠右，在窄屏下换行并保持完整可点击。

## 6. 公共组件

### 6.1 卡片和指标

- 统一卡片边框、圆角、内边距、图标底色和阴影。
- 仪表盘指标卡保留当前真实数据，不使用原型模拟数据。
- 成功、警告、危险、信息和 AI 状态保持语义色一致。

### 6.2 表格和列表

- 表格放置于圆角白色容器中。
- 表头使用浅色背景和较弱分隔线。
- 行悬停、选中、不可用、错误和空状态必须可区分。
- 商品图、SKU、金额、库存、状态和操作列保持当前数据与交互。
- 窄屏允许表格横向滚动，但不得造成整个页面横向溢出。

### 6.3 表单、筛选和分页

- 输入框、选择器、日期选择、数字输入、开关和按钮统一高度、圆角与焦点环。
- 查询区使用独立浅色工具栏或卡片，不改变查询参数或提交行为。
- 分页、页容量和统计信息保持现有 contract。

### 6.4 弹窗、抽屉和反馈

- Modal、Drawer、Popover、Dropdown、Tooltip、Alert 和 Empty 统一套用视觉令牌。
- 加载、成功、失败、禁用、空数据和权限不足状态保持当前业务逻辑。
- 不用颜色作为唯一状态提示；继续保留文字、图标或标签。

## 7. 页面覆盖范围

本次覆盖目标项目中所有现有路由及其主要状态，包括：

- 登录与账号检查
- 仪表盘和数据大屏
- 商品列表、采集箱、商品编辑、上架记录、库存、下架重上
- 选品、AI 改图、AI 商品套图
- 价格折扣、促销活动、自动删促销
- 订单、退货、利润趋势
- 消息任务、消息模板、发送记录
- 水印、商品模板
- 经营店铺、账号管理、算价配置
- 浏览器插件页面及现有抽屉、弹窗、筛选和操作菜单
- 404 页面

原型没有直接对应页面时，沿用本设计系统，不新增业务功能或页面。

## 8. 响应式设计

### 8.1 桌面端

- 主要验收宽度：1440px。
- 侧栏固定或稳定占位，内容区域不得被顶部操作区遮挡。
- 复杂卡片和表格按业务优先级分栏。

### 8.2 中等宽度

- 主要验收宽度：1280px 和 1024px。
- 侧栏可收窄，顶部控件可隐藏次级说明。
- 卡片列数逐级减少。
- 不复制参考原型在 1280px 下的横向裁切。

### 8.3 移动端

- 主要验收宽度：390px。
- 使用紧凑顶栏和可展开导航。
- 卡片、筛选区和表单转为单列。
- 表格在自身容器内横向滚动。
- 主要操作保持可见、可点击，触控目标不小于约 40px。

## 9. 技术边界

优先修改：

- `app/src/styles.css`
- `app/src/App.jsx` 中与布局、公共结构和样式类名相关的最小代码

只有在主题配置无法覆盖时，才调整 Ant Design `ConfigProvider` token。不得修改：

- API 路径、请求参数或响应解析
- 数据库、迁移、服务端代码
- 权限、账号和店铺数据边界
- 订单、库存、金额、汇率、上架和同步业务规则
- 浏览器扩展、桌面采集器和外部服务
- 依赖和锁文件

## 10. 数据流与错误处理

本次不改变数据流。页面仍通过现有组件状态和 API 获取数据，视觉层只消费既有状态。

- 接口加载中：使用统一加载样式，不隐藏已有进度信息。
- 接口失败：保留现有错误消息和重试入口。
- 无店铺、无数据或未授权：保留当前引导和禁用逻辑。
- 重复操作、同步任务和外部调用：幂等与恢复行为完全由现有逻辑负责，本次不改动。

## 11. 验收标准

### 11.1 视觉

- 所有现有页面使用同一背景、字体、色彩、圆角、边框和阴影体系。
- 应用外壳与参考原型在布局、层级和密度上明显一致。
- 关键页面不存在错位、裁切、遮挡、异常留白或整页横向溢出。
- 桌面端和移动端使用相同设计语言。

### 11.2 业务

- 页面路由、查询、筛选、标签页、菜单、弹窗、抽屉和主要按钮仍可用。
- 现有数据、金额、订单、库存、店铺和任务状态不因样式改造而改变。
- 后端 contract、权限和外部调用保持不变。

### 11.3 工程验证

- `pnpm --dir app build` 通过。
- 现有适用的前端或全仓验证命令通过，或明确记录基线失败。
- 核心路由完成浏览器冒烟检查。
- 仪表盘、商品、订单、利润、店铺和算价页面完成桌面截图检查。
- 至少对首页和一个表格页面完成 390px 移动端检查。
- 参考原型截图与目标页面截图在相同视口下进行并排视觉比较。

## 12. 风险与控制

- 当前 `App.jsx` 和 `styles.css` 文件较大，选择器覆盖可能影响多个页面。通过设计令牌、公共选择器和小批次验证控制风险。
- 当前工作区已有大量未提交用户改动。实施时不得覆盖、格式化或吸收无关修改。
- 若必须修改超出 `app/src/App.jsx` 和 `app/src/styles.css` 的文件，应先更新影响分析并重新确认风险。
- 不安装依赖，不改锁文件，不运行真实 Ozon 写操作，不触碰生产数据。

- 不使用 `git reset --hard`、`git checkout --` 或其他会破坏现有工作区的命令。

## 14. 明确非目标

- 不把原型模拟数据复制到目标项目。
- 不新增页面、业务功能或外部集成。
- 不重构服务端、数据库或浏览器扩展。

- 不部署、不发布、不提交真实凭据。
