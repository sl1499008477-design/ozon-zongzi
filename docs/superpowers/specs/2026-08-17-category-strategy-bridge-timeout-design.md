# 类目策略扩展桥接超时设计

## 目标

Chrome MV3 扩展后台冷启动时，即使扩展已登录且服务端就绪请求最终成功，类目策略页也不能在 1.5 秒时误报“扩展尚未连接”。

## 最小方案

- 保持现有调用顺序：管理页等待扩展向服务端登记就绪，服务端确认后才创建或恢复采集会话。
- 仅将 Web 与扩展消息桥的默认等待上限从 1.5 秒调整为 15 秒，并允许测试或调用方传入不超过 30 秒的明确上限。
- 不增加重试、轮询、后台常驻、绕过鉴权或新的抽象层。
- 超时后继续返回原有稳定错误，不改变公开错误码和用户提示。

## 安全与行为边界

- 保留扩展版本、采集凭证、账号权限、账号隔离和服务端就绪校验。
- 不改变精确类目、会话密钥、样品数量、人工确认和上传边界。
- 本批次不选择样品、不确认策略、不上传，也不修改数据库结构。

## 验证

- 先新增一个使用默认配置、在旧 1.5 秒边界之后返回有效回执的失败测试。
- 最小修改后运行扩展桥测试和相关类目策略测试。
- 重新构建扩展并在真实 Chrome 中验证“继续选样”能恢复会话、打开正确类目列表并显示选样控件。
