# 多变体草稿兼容归一化设计

## 目标

修复采集商品编辑页读取多变体草稿时的字段错位：数据库已保存来源变体的 `sku`、`name`、`price`，但页面表格使用 `offerId`、`name`、`sellPrice`，导致货号和售价显示为空并阻止上架准备。

## 已确认事实

- 商品 `collect_01f58aaf31bf8bdc28434a29` 的两个来源变体均已保存 SKU、名称、价格和图片。
- 页面直接加载 `listingDraft.variants` 时只补 `key` 和 `index`，没有执行现有的变体表格转换。
- 页面表格和必填校验读取 `offerId`、`name`、`sellPrice`。
- 当前页面名称可见，实际缺失的是目标货号和售价；“货号、名称和售价”是合并提示。

## 方案比较

### 方案 A：页面读取时统一归一化（采用）

把持久化草稿变体统一转换成页面稳定行结构。已有页面字段优先；缺失时才从来源字段补齐。

优点：兼容历史数据，无数据库迁移，不修改采集与后端 contract，人工编辑不会被覆盖。

### 方案 B：批量重写数据库草稿

把所有旧草稿转换后写回数据库。

缺点：需要迁移和回滚，可能覆盖历史人工编辑，对当前问题没有必要。

### 方案 C：让表格和校验同时读取两套字段

在每个输入框、校验和提交位置分别增加 `price/sellPrice`、`sku/offerId` 回退。

缺点：字段兼容逻辑分散，容易出现显示、校验、提交结果不一致。

## 组件边界

新增一个纯函数模块，负责把一条持久化变体变成页面表格行：

- 输入：持久化变体、序号、主 SKU、主标题、主价格、图片、货号前缀。
- 输出：稳定的 `key/index/sku/offerId/name/sellPrice/oldPrice/stock` 等页面字段。
- 已有 `offerId`、`sellPrice`、人工名称、划线价、库存必须优先保留。
- 缺失 `offerId` 时，以 `offerPrefix + sku` 生成；多变体追加稳定序号，避免货号重复。
- 缺失 `sellPrice` 时按 `price.price → priceText → price → marketingPrice` 回退。
- 不猜测不存在的来源数据，不发起外部调用。

`App.jsx` 的初始化流程对草稿变体和来源变体都调用同一归一化入口，不再因为 `draft.variants` 存在而绕过转换。

## 数据流

1. Web 从本地 API 读取采集商品及 `listingDraft.variants`。
2. 归一化函数保留已有页面字段，并从来源字段补缺失字段。
3. React 状态只接收稳定表格行 contract。
4. 表格显示、必填校验、草稿保存和上架预览继续消费同一行结构。

## 验收标准

- 当前两个变体分别显示来源名称和售价 `30.84`、`29.06`。
- 两个变体自动生成非空且互不重复的目标 SKU 货号。
- 底部不再因为这两个变体提示“变体 SKU 货号、名称和售价”。
- 已保存的 `offerId`、`sellPrice`、人工名称、划线价和库存不被重新生成或覆盖。
- 单变体的既有生成逻辑保持不变。
- 不修改数据库、后端 API、扩展采集 contract，不触发保存或真实上架。

## 测试

- 纯函数测试：真实来源字段形状可以生成完整的两条页面行。
- 兼容测试：已编辑页面字段优先于来源字段。
- 边界测试：嵌套价格和多变体货号序号正确。
- 回归：全部 `app/tests/*.test.mjs`、前端生产构建、真实页面只读核对。

## 回滚

回滚前端归一化模块、测试及 `App.jsx` 接入即可；数据库没有变更，不需要数据恢复。
