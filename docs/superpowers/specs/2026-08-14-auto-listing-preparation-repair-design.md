# 自动上架任务创建修复设计

## 目标

修复“粽子测试”人民币店铺创建自动上架生成任务时只显示“自动上架请求处理失败”的问题。用户不填写店铺币种，也不手工判断 Ozon 类目是否迁移；系统以该店铺的 Ozon 权威资料和实时类目树为准。

## 已确认根因

1. 店铺凭据读取端口只返回账号、店铺、Client-Id 和 Api-Key，遗漏已经由 `/v1/seller/info` 确认并持久化的 `currencyCode=CNY`。生成底稿因此把空币种与冻结的 CNY 价格证据比较并误判失败。
2. 商品类型 `94453` 仍存在，但 Ozon 已把它从旧 description category `17033252` 移到当前 category `17029005`。旧组合调用属性接口得到 Ozon 400 `category ... is not found`。
3. 路由没有把准备阶段的安全错误码映射为可理解文案，所以页面只显示笼统的 500 错误。

## 业务规则

- 店铺币种只来自同租户目标店铺已验证的 `OZON_SELLER_INFO` 记录；凭据读取不得接受未同步币种的店铺。
- 创建前用同一店铺凭据读取 Ozon 当前类目树。若保存的 type 仍是唯一启用叶子，但 description category 已迁移，则在独立事务中按共享类目版本 CAS 更新为 `OZON_REFRESH`，保留旧来源证据和追加事件。
- 类目刷新后必须重新读取商品来源并重新取得类目准备租约，不能在旧租约或旧快照上继续。
- type 不存在、重复或不唯一时失败关闭，提示管理员处理；不得猜测相似名称或类目。
- Ozon 类目树、属性或字典读取不可用时，不创建任务、不调用 AI、不创建商品、不修改库存。
- 相同请求重放继续受已有幂等键约束，不产生重复任务或外部副作用。

## 接口与数据流

1. `auto-listing-category-access-postgres` 返回闭合的店铺访问对象，并带权威 `currencyCode`。
2. 自动上架服务在取得目标店铺与来源后、取得准备租约前调用新的类目 freshness port。
3. freshness port 对每个共享类目做实时树核验：
   - 当前组合有效：返回 `CURRENT`，零写入；
   - type 唯一迁移：调用现有 shared repository 的 invalidate/activate CAS，返回 `REFRESHED`；
   - 不唯一或不可用：返回稳定安全错误。
4. 任一来源被刷新时，服务重新加载全部来源，再进入租约、底稿、RFBS 验证和任务图创建。

## 错误与页面

- `AUTO_LISTING_CATEGORY_REFRESH_REQUIRED`：共享类目刚被刷新但来源重读未闭合，提示刷新页面后重试。
- `AUTO_LISTING_CATEGORY_NEEDS_REVIEW`：Ozon 当前类目无法唯一确定，提示管理员处理类目。
- `AUTO_LISTING_CATEGORY_ATTRIBUTES_INCOMPLETE`：当前类目属性暂不可用，提示稍后重试。
- 所有文案固定，不透传 Ozon 原始响应、凭据或内部异常。

## 验收

- 单元 RED 复现店铺访问端口漏币种；GREEN 返回 CNY 且只允许权威同步记录。
- 服务 RED 复现旧 category + 唯一现 type；GREEN 先刷新共享类目、重读来源、再创建一次任务图。
- 不唯一/树不可用/版本冲突均在 AI、商品和库存写入前停止。
- 真实 PostgreSQL 验证同账号共享类目从 `17033252/94453` 更新为 `17029005/94453`，旧证据不变、事件追加、第二店可复用。
- 用当前商品执行只读底稿准备，结果为 CNY 且属性读取成功；不自动点击页面创建任务。

## 回滚

- 应用代码独立提交，可通过 `git revert` 回滚。
- 共享类目刷新是审计型向前状态变化，不删除旧证据；回滚应用时保留已写事件和当前版本。
- 若 freshness port 异常，关闭自动上架新任务创建，不能把旧类目强行恢复或绕过 Ozon 校验。
