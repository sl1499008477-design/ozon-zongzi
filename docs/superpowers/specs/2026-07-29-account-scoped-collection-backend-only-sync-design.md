# 账号级统一采集箱与后端唯一同步设计

日期：2026-07-29

状态：已确认，待实施计划

适用范围：Web、后端、浏览器插件、桌面采集、数据库迁移与测试门禁

## 1. 背景

当前项目同时存在两套店铺同步实现：

- 浏览器插件直接连接 Ozon Seller API，同步商品、FBS 订单和仓库；
- Web 请求后端，由后端连接 Ozon Seller API，同步店铺资料、商品、价格、库存、FBS/FBO 订单、仓库和促销。

两套实现的数据范围并不一致。插件商品同步没有独立刷新价格和 FBS/FBO 商品库存，不同步 FBO 订单，也不会清理已经不存在的商品；后端同步的数据更完整。Web 当前会先尝试插件同步，插件不可用时再回退到后端，导致内置浏览器中出现误导性的“插件同步失败”提示和额外等待。

项目还存在“经营店铺”和“数据店铺”两套店铺概念。数据店铺贯穿 Web、后端、插件、桌面采集和数据库表，用户采集前需要额外绑定或校验数据店铺，增加了理解和操作成本。

本设计统一职责：

- Web 负责登录、经营店铺管理、同步控制和结果展示；
- 后端负责全部 Seller API 同步、权限、存储、审计、幂等和恢复；
- 插件只负责网页数据抓取与采集结果上传；
- 采集数据统一归属账号，采集时不绑定店铺，上架时再选择目标经营店铺。

## 2. 目标

1. 删除插件直接连接 Ozon Seller API 的同步能力。
2. 删除插件发送店铺同步指令的能力。
3. Web 店铺同步只调用后端同步接口。
4. 删除插件独立登录界面，插件复用 Web 登录状态。
5. 插件只获得权限受限、短期有效的采集会话。
6. 删除数据店铺的用户功能和运行时依赖。
7. 采集数据只以 `account_id` 作为业务归属。
8. 允许没有经营店铺的账号正常采集。
9. 准备上架时必须选择目标经营店铺，并冻结目标店铺快照。
10. 迁移过程中保留历史数据、来源证据和回滚能力。

## 3. 非目标

- 不改变 Ozon Seller API 的业务含义。
- 不允许插件直接正式上架或修改 Ozon 商品。
- 不在第一次发布中物理删除数据店铺历史表。
- 不把历史数据自动归给无法可靠确定的账号。
- 不允许匿名采集上传。
- 不把 Web 的完整登录令牌长期复制给插件。

## 4. 总体架构

### 4.1 职责边界

#### Web

- 账号登录、退出和会话管理；
- 经营店铺的绑定、切换、停用和删除；
- 发起店铺同步并展示每种类型的进度和结果；
- 展示账号级统一采集箱；
- 在准备上架时选择目标经营店铺；
- 为已登录账号申请一次性插件采集通行证。

#### 后端

- 在后端校验所有账号、店铺和采集权限；
- 保存并加密 Ozon Client ID 与 API Key；
- 连接 Ozon Seller API；
- 同步店铺资料、商品、价格、库存、仓库、FBS/FBO 订单和促销；
- 签发和验证插件采集通行证与采集会话；
- 以账号为边界接收采集数据；
- 执行幂等、审计、失败记录和恢复；
- 在创建上架草稿时验证并冻结目标经营店铺。

#### 浏览器插件

- 检查 Web 是否已登录；
- 未登录时展示说明和“前往登录”按钮；
- 用一次性通行证换取短期采集会话；
- 抓取 Ozon、1688 等网页中需要浏览器上下文的数据；
- 标准化、暂存并上传抓取结果；
- 管理待上传队列和上传状态；
- 不同步店铺数据，不发送同步指令，不读取店铺 API Key，不执行正式上架。

### 4.2 主要数据流

#### 店铺同步

```text
Web 发起同步
  -> 后端创建同步任务
  -> 后端读取当前账号选择的经营店铺
  -> 后端连接 Ozon Seller API
  -> 后端按类型同步并提交结果
  -> Web 读取任务状态并展示
```

插件不参与任何步骤。

#### 网页采集

```text
插件确认采集会话
  -> 插件抓取网页
  -> 插件生成 requestId 和来源证据
  -> 插件上传到后端
  -> 后端从采集会话取得 accountId
  -> 后端幂等写入账号级采集箱
  -> Web 展示采集结果
```

#### 准备上架

```text
账号级采集箱选择商品
  -> 用户选择目标经营店铺
  -> 后端验证店铺归属、状态和凭据
  -> 后端生成绑定目标店铺快照的上架草稿
  -> 后端安全上架管道执行正式外部写入
```

## 5. 插件采集会话

### 5.1 会话原则

- 用户只在 Web 登录一次，插件没有账号密码表单；
- 插件不能读取 Web 页面本地存储；
- 插件不能获得 Web 的完整账号会话权限；
- 插件会话必须在后端验证；
- 插件会话与签发它的 Web 会话、账号和设备绑定；
- Web 会话失效时，其派生的插件会话同时失效。

### 5.2 API contract

#### `POST /extension/collector-auth/ticket`

调用者：已登录 Web 用户。

行为：

- 后端校验 Web 会话；
- 创建一次性通行证；
- 通行证有效期 60 秒；
- 通行证只能交换一次；
- 通行证不得写入日志和审计 metadata。

响应：

```json
{
  "ticket": "opaque-one-time-value",
  "expiresAt": "ISO-8601"
}
```

#### `POST /extension/collector-auth/exchange`

调用者：插件。

请求：

```json
{
  "ticket": "opaque-one-time-value",
  "deviceFingerprint": "stable-device-id",
  "extensionVersion": "manifest-version"
}
```

行为：

- 原子消费一次性通行证；
- 签发最长 8 小时、且不超过父 Web 会话有效期的采集会话；
- 采集会话与 `account_id`、父 Web 会话和设备绑定；
- 只授予：
  - `collector.upload`
  - `collector.job.read`
  - `collector.config.read`

响应：

```json
{
  "collectorToken": "opaque-scoped-token",
  "expiresAt": "ISO-8601",
  "account": {
    "id": "account-id",
    "displayName": "display-name"
  }
}
```

#### `GET /extension/collector-auth/status`

调用者：持有采集会话的插件。

响应只包含：

```json
{
  "authenticated": true,
  "expiresAt": "ISO-8601",
  "account": {
    "id": "account-id",
    "displayName": "display-name"
  },
  "permissions": [
    "collector.upload",
    "collector.job.read",
    "collector.config.read"
  ]
}
```

不返回经营店铺、API Key、完整账号资料或普通 Web token。

### 5.3 服务端保存规则

后端新增独立的通行证和采集会话存储：

- 通行证只保存不可逆摘要，不保存可直接使用的明文；
- 采集令牌只保存不可逆摘要；
- 通行证记录包含 `account_id`、父 Web 会话、创建时间、过期时间和消费时间；
- 采集会话记录包含 `account_id`、父 Web 会话、设备标识、权限、过期时间、撤销时间和最近使用时间；
- 通行证消费必须使用数据库原子更新，两个并发交换请求只能有一个成功；
- 每次采集上传都重新检查账号状态、父 Web 会话状态、采集会话状态和权限；
- 通行证签发、交换、撤销和采集会话拒绝必须写脱敏审计，不记录令牌正文。

### 5.4 Web 与插件的通行证交付

- 插件只能在受信任的 Web 来源请求通行证；
- Web 页面使用现有受控桥接机制发送新的 `collector.auth.request` 和 `collector.auth.response` 消息；
- 旧的 `syncAuthFromWeb` 动作删除，不能继续传递完整 Web token；
- 桥接层必须校验来源协议、主机、端口、消息类型和一次性请求 ID；
- 响应只包含一次性通行证和过期时间；
- 页面中的其他脚本即使重复发送同一个通行证，也只能有一次交换成功；
- 插件未找到已登录 Web 页面时，不猜测登录状态，直接展示“前往登录”。
- Web 登录必须发生在安装该插件的同一浏览器配置中；其他浏览器或内置浏览器中的登录状态不能被插件继承；
- “前往登录”必须在安装插件的浏览器中打开 Web 登录页；
- 插件成功交换采集会话后，Web 页面可以关闭，插件在会话有效期内继续采集。

### 5.5 插件端保存规则

- 采集会话只保存在 `chrome.storage.session` 或等价的浏览器会话存储；
- 浏览器关闭后自动清除；
- 不写入同步存储或永久本地存储；
- 不在日志、错误消息、抓取文件或导出文件中输出通行证和令牌；
- 401/403 时清除采集会话并重新检查 Web 登录状态。

### 5.6 未登录体验

插件未取得有效采集会话时只显示：

- “请先登录 Web 管理后台，再使用采集功能”；
- “前往登录”按钮；
- “重新检查”按钮。

“前往登录”打开受信任的 Web 登录地址。登录成功后，Web 页面可以主动通知插件重新申请一次性通行证，但不能把完整 Web token 发给插件。

## 6. 账号级统一采集箱

### 6.1 新业务归属

每条新采集记录必须至少保存：

- `account_id`
- `created_by`
- `source`
- `source_sku` 或稳定来源标识
- `source_url`
- `raw_payload` 或原始证据引用
- `captured_at`
- `request_id`
- `device_fingerprint`
- `content_hash`

采集阶段不要求：

- `store_id`
- `operating_store_id`
- `data_collection_store_id`
- `seller_company_id`

插件请求中的 `accountId`、`createdBy` 和店铺字段不可信。后端必须从已验证的采集会话派生 `account_id` 和 `created_by`，忽略或拒绝客户端伪造值。

### 6.2 幂等

插件为一次抓取生成稳定 `requestId`。后端幂等键至少包含：

```text
account_id + source + source_sku + request_id
```

相同账号、相同请求编号和相同 payload 重放时返回第一次结果；相同请求编号但 payload 不同时返回冲突，不产生第二条记录。

### 6.3 多账号隔离

- 所有查询、更新、删除、导出和上架准备都以 `account_id` 过滤；
- 采集会话不能覆盖请求中的账号边界；
- 账号 A 的待上传记录不能使用账号 B 的会话上传；
- 插件待上传队列必须记录创建它的账号会话标识；
- Web 切换账号时，旧账号待上传项保留但停止上传，直到重新进入原账号会话。

### 6.4 上架目标店铺

采集记录不绑定经营店铺。用户点击“准备上架”时：

1. Web 要求用户选择目标经营店铺；
2. 后端验证店铺属于当前账号且状态可用；
3. 后端验证店铺凭据已保存且可用于上架；
4. 上架草稿保存不可变的 `target_store_id` 与必要快照；
5. 后续发布不能因“当前店铺”切换而改变目标。

## 7. 删除插件同步

### 7.1 删除能力

从插件删除：

- `sync-engine.js`
- `opi-client.js`
- `lease-client.js`
- 商品、订单和仓库同步闹钟；
- 自动同步调度和同步间隔配置；
- `jzManualSync`
- `sync.request`
- `sync.response`
- 插件同步状态、同步按钮和同步错误提示；
- 获取 Seller API 同步凭据的调用；
- 同步 lease、heartbeat、client-report 和 import-with-hash 调用；
- 插件直接访问 `api-seller.ozon.ru` 的权限和代码。

现有 `backend-client.js` 还包含采集、AI 草稿和浏览器任务接口，不能整体删除。实施时应拆分为职责单一的采集客户端和必要的浏览器任务客户端，只移除同步相关方法。

### 7.2 Web 同步

Web 的“同步全部”不再检测插件，不再等待插件响应，不再执行 fallback 分支。Web 直接为以下类型调用后端：

1. `WAREHOUSES`
2. `PRODUCTS`
3. `POSTINGS`
4. `PROMOTIONS`

页面按类型显示：

- `PENDING`
- `RUNNING`
- `SUCCESS`
- `FAILED`

一个类型失败时保留已经成功的类型结果，并允许单独重试失败类型。

### 7.3 后端唯一同步范围

后端同步 contract 必须继续覆盖：

- 店铺基本资料；
- 商品列表与档案商品；
- 商品详情；
- 最新价格、促销价和价格信息；
- FBS/FBO 商品库存；
- 仓库列表；
- FBS 订单；
- FBO 订单；
- 促销活动；
- 已不存在商品的缓存清理；
- 每种类型的任务状态和错误信息。

## 8. 删除数据店铺功能

### 8.1 用户可见功能

删除：

- 数据店铺列表；
- 数据店铺新增、修改、删除和切换；
- 当前数据店铺；
- 数据店铺登录校验；
- 采集任务的数据店铺选择；
- 数据店铺筛选条件；
- “请先绑定数据店铺”类阻断提示；
- 插件和桌面端的 Seller Company ID 与数据店铺匹配逻辑。

### 8.2 运行时 contract

从新 contract 删除：

- `dataCollectionStoreId`
- `currentDataCollectionStoreId`
- `currentDataCollectionStoreIdsByAccount`
- `dataCollectionStore`
- `dataCollectionStores`

采集、任务、运行、导出、市场快照和采集箱查询统一以 `account_id` 为强制范围。采集阶段的 `store_id` 和 `operating_store_id` 允许为空。

### 8.3 历史数据兼容迁移

第一次迁移不得直接删除旧表或历史字段。

迁移步骤：

1. 检查每条历史采集记录是否已有可靠 `account_id`；
2. 缺少 `account_id` 时，只能从唯一的数据店铺成员关系、任务账号或其他权威外键回填；
3. 如果存在多个可能账号或没有权威映射，迁移失败并报告记录 ID，不允许猜测；
4. 使采集相关表的 `store_id`、`operating_store_id`、`data_collection_store_id` 在采集阶段允许为空；
5. 新代码停止读写 `data_collection_store_id`；
6. 保留旧字段和旧表作为只读历史证据；
7. 完成数量、账号归属和引用完整性验证后，再单独设计物理删除迁移。

功能删除不等于历史证据删除。第一次发布后，用户和运行时代码都不能再使用数据店铺，但旧数据仍可用于恢复和核对。

## 9. 异常处理

### 9.1 Web 未登录

- 插件不允许抓取上传；
- 显示前往 Web 登录按钮；
- 不创建匿名本地数据；
- 已经完成但尚未上传的抓取结果进入待上传队列。

### 9.2 通行证过期

- 插件自动重新申请一次；
- 第二次失败则停止上传并提示登录；
- 不丢弃已经抓取的数据。

### 9.3 网络中断

- 抓取结果进入按账号隔离的待上传队列；
- 网络恢复后使用原 `requestId` 重试；
- 后端幂等保证重复请求不产生重复记录；
- 后端确认成功后才能删除本地待上传项。

### 9.4 账号切换

- 旧账号采集会话立即失效；
- 旧账号待上传项不能用新账号会话上传；
- 插件提示存在属于上一个账号的待上传数据；
- 重新登录原账号后才允许继续上传。

### 9.5 上架时没有店铺

- 采集箱仍可正常使用；
- 点击准备上架时提示先绑定经营店铺；
- 未选择并验证目标店铺时不生成可发布草稿。

### 9.6 后端同步失败

Web 按类型显示成功数量和失败原因。失败类型可以单独重试，成功类型不重复执行。所有失败报告必须包含任务 ID、账号、店铺、类型、发生时间和已脱敏错误信息。

## 10. 测试与验证

### 10.1 插件认证

- 插件不存在账号密码登录表单；
- Web 未登录时插件不能获得采集会话；
- 一次性通行证只能消费一次且 60 秒后失效；
- 采集会话不超过 8 小时且不超过父 Web 会话；
- Web 退出、密码修改、账号停用或删除会撤销插件会话；
- 采集会话不能调用账号、店铺、同步和正式上架接口；
- 通行证和令牌不进入日志。

### 10.2 数据隔离和幂等

- 没有经营店铺时可以采集；
- 新采集记录只有账号归属，不需要数据店铺；
- 账号 A 不能读取、修改、导出或上架账号 B 的采集数据；
- 账号 A 的待上传数据不能用账号 B 的会话上传；
- 同一 `requestId` 重试不会产生重复数据；
- 同一 `requestId` 携带不同 payload 返回冲突。

### 10.3 插件同步删除门禁

- 插件源码不包含对 `api-seller.ozon.ru` 的请求；
- 插件 manifest 不再声明 Seller API 同步权限；
- 不存在 `jzManualSync`、`sync.request`、`sync.response`；
- 不存在商品、订单、仓库同步闹钟；
- 不加载 `sync-engine.js`、`opi-client.js`、`lease-client.js`；
- Web 同步不会等待插件响应。

### 10.4 后端同步回归

- 商品基本信息、价格、促销价和 FBS/FBO 库存同步；
- 档案商品同步；
- 已不存在商品清理；
- FBS/FBO 订单同步；
- 仓库和促销同步；
- 店铺资料刷新；
- 单类型失败可重试且不会覆盖其他类型成功结果；
- 多账号、多店铺数据隔离。

### 10.5 数据店铺迁移

- 历史记录迁移前后数量一致；
- 每条历史记录账号归属一致；
- 无法唯一确定账号的记录使迁移失败并输出记录标识；
- 新记录不读写 `data_collection_store_id`；
- 用户界面、API 和插件中不存在数据店铺入口；
- 上架草稿必须有目标经营店铺。

### 10.6 旧功能回归

- Ozon 和 1688 页面抓取；
- 图片、规格和原始响应保存；
- 采集箱查询、筛选、编辑、删除和导出；
- AI 草稿生成；
- 目标店铺选择和安全上架；
- Web 登录、退出、多账号切换；
- 经营店铺绑定、切换和后端同步。

## 11. 发布顺序

1. 先部署兼容的数据库迁移和后端采集会话接口；
2. 部署支持账号级采集箱和后端唯一同步的 Web；
3. 发布移除同步与独立登录的新插件；
4. 将旧插件同步端点改为明确的 `410 EXTENSION_SYNC_REMOVED`，提示更新插件，不执行外部同步；
5. 验证新插件采集、账号隔离和 Web 后端同步；
6. 删除运行时数据店铺页面、接口和依赖；
7. 运行历史数据数量、归属和引用完整性检查；
8. 稳定运行并完成备份后，再单独评审物理删除旧表的迁移。

## 12. 回滚

- 第一次迁移只增加新会话结构、放宽采集阶段店铺字段并停止使用旧字段，不删除历史表；
- 应用出现问题时可以回滚 Web、后端和插件代码；
- 历史数据店铺表和字段仍保留，可供旧版本读取；
- 新账号级采集数据始终具有 `account_id`，回滚不会丢失；
- 插件可以回退到上一个安装包，但旧同步端点是否临时恢复必须由后端版本一起决定；
- 任何物理删除旧表的后续迁移都必须在独立备份和独立审批后执行。

## 13. 验收标准

1. 用户只需登录 Web，不需要在插件再次输入账号密码。
2. Web 未登录时插件明确提示并可直接打开登录页。
3. 插件只持有权限受限的短期采集会话。
4. 插件不能执行或触发任何店铺同步。
5. 插件不再直接访问 Ozon Seller API。
6. Web 店铺同步全部由后端执行，数据范围保持完整。
7. 用户无需绑定数据店铺即可采集。
8. 所有新采集数据归属当前账号。
9. 上架时必须选择目标经营店铺，且任务执行期间目标不能被当前店铺切换改变。
10. 历史采集数据数量不减少、账号归属不变化。
11. 重复上传不产生重复数据。
12. 多账号之间不存在采集、同步或上架数据串用。
