# RFBS 新店首次自动上架仓库设计

日期：2026-08-11
状态：已获用户批准，待实施计划
范围：自动上架仓库资格、验证证据、任务冻结、上传前复核与管理页面提示

## 背景与问题

当前自动上架只接受具备未归档商品关联的活跃 FBS 仓库。资格判断、配置保存、任务创建、上传证据读取和最终提交事务都重复执行这条规则。

当前店铺“粽子测试”只有一个 Ozon 平台仓库 `CEL-测试`：

- 仓库类型为 `rFBS`；
- 平台仓库 ID 有效；
- 本地状态为可用；
- 店铺尚无商品和库存关联。

因此它同时被 `TYPE_NOT_FBS` 和 `NO_ACTIVE_PRODUCT_ASSOCIATION` 两条现有规则排除。只修改前端下拉框无法形成可用闭环，直接取消后端校验又会破坏店铺、租户和平台仓库边界。

## 业务目标

允许没有历史商品的活跃 RFBS 仓库用于新店首次自动上架，同时保证：

1. 仓库必须真实属于当前账号下的目标店铺；
2. 仓库类型、平台 ID 和状态来自后端只读验证，不能信任浏览器输入；
3. 创建任务时冻结验证证据，执行上传时重新检查，不能使用已变化或过期证据；
4. 商品创建和库存更新保持幂等，库存失败不得重复创建商品；
5. FBS、其他仓库类型和跨店铺边界不能被意外放宽；
6. 不在开发和自动测试中发起真实 Ozon 写请求。

## 非目标

- 不支持 FBO、FBP 或未知仓库类型自动上架；
- 不改变定价、图片生成、富文本、审核、DIRECT 发布策略或 AI 模型配置；
- 不自动创建、启用或修改 Ozon 仓库；
- 不把浏览器返回的仓库类型或验证结果作为可信证据；
- 不在本次开发中完成真实商品写入验收，真实写入必须另行获得明确授权。

## 方案选择

采用“RFBS 安全首次上架”方案：

- FBS 继续要求现有的未归档商品关联证据；
- RFBS 不要求历史商品关联，但必须持有新鲜、成功、租户绑定的只读仓库验证证据；
- FBO、FBP 和未知类型继续失败关闭；
- 任务创建与最终上传分别校验，避免只在页面展示层放宽。

未采用以下方案：

- **直接允许 RFBS 且不验证**：改动较小，但会允许陈旧、停用或错店仓库；
- **单独 RFBS 试验开关**：更保守，但增加管理员配置和运行分支，本地单店测试没有足够收益。

## 核心资格规则

统一资格函数输出稳定、可追溯的结果：

```json
{
  "eligible": true,
  "code": "ELIGIBLE_ACTIVE_RFBS",
  "fulfillmentType": "RFBS",
  "evidenceRequired": true
}
```

资格矩阵：

| 仓库类型 | 商品关联 | 新鲜只读验证 | 结果 |
| --- | --- | --- | --- |
| FBS | 有未归档商品关联 | 不新增要求 | 允许，保持现有行为 |
| FBS | 无商品关联 | 任意 | 拒绝 `NO_ACTIVE_PRODUCT_ASSOCIATION` |
| RFBS | 任意 | 成功且未过期 | 允许 `ELIGIBLE_ACTIVE_RFBS` |
| RFBS | 任意 | 缺失、失败或过期 | 拒绝 `RFBS_VALIDATION_REQUIRED` |
| FBO/FBP/未知 | 任意 | 任意 | 拒绝 `UNSUPPORTED_FULFILLMENT_TYPE` |

所有允许分支仍必须满足：

- `accountId`、`storeId` 和本地仓库记录严格一致；
- Ozon 平台 `warehouse_id` 存在，且不是内部占位 ID；
- 仓库没有停用、归档、删除或 blocked 状态；
- 当前账号拥有目标店铺且店铺凭证可用。

现有 `TYPE_NOT_FBS` 对外兼容读取可以保留，但新提交路径应使用更明确的 `UNSUPPORTED_FULFILLMENT_TYPE`；错误响应不得包含仓库原始响应、API Key 或其他租户数据。

## 只读验证证据

### 证据来源

后端通过现有 Ozon Seller 仓库列表读取能力获取当前店铺仓库，不接受前端传入的仓库类型或状态。请求只读取仓库列表，不创建商品、不更新库存。

验证必须在当前账号和目标店铺凭证范围内执行，并精确找到选中的平台仓库 ID。结果至少冻结：

- `accountId`；
- `storeId`；
- 本地仓库记录 ID；
- Ozon 平台仓库 ID；
- 规范化仓库类型 `RFBS`；
- 规范化状态；
- 验证时间与过期时间；
- 证据摘要；
- 成功或安全失败结果；
- correlation ID 和执行主体。

### 持久化

新增 forward-only migration `059`：

- 建立 append-only 的 RFBS 仓库验证证据表；
- 证据使用账号、店铺、本地仓库和平台仓库的复合边界；
- 成功证据默认有效期 10 分钟；
- 任务记录新增 nullable 的验证证据引用；
- FBS 历史任务和既有数据保持 `NULL`，无需回填；
- UPDATE/DELETE 由数据库触发器禁止，账号隐私删除沿用项目既有的受控级联规则。

证据摘要只覆盖规范化后的安全字段，不保存 API Key，也不把完整第三方响应放入公开 DTO 或普通日志。必要的原始响应引用只能进入现有受限证据存储。

## 数据流

### 页面加载

1. 本地状态同步继续保存完整仓库记录。
2. FBS 按现有商品关联规则计算资格。
3. RFBS 仓库显示为“需要验证”或“验证通过”；页面不能自行把 RFBS 标为可用。
4. 下拉框标题改为“活跃 FBS / RFBS 仓库”，并显示类型和验证状态。

### 保存配置与创建任务

1. 用户选择 RFBS 仓库并创建任务。
2. 后端完成权限、账号、店铺和仓库本地边界校验。
3. 后端发起一次只读仓库验证。
4. 成功后写入不可变证据，并在创建任务的同一事务中绑定证据 ID。
5. 同一幂等键重放返回原任务和原证据，不重复创建任务。
6. 验证失败时返回稳定错误，不创建任务，不调用商品导入或库存更新接口。

### 上传执行

1. Worker 读取任务冻结的仓库证据。
2. 若证据未过期，先在事务外只读复核当前仓库；若已过期，必须重新生成成功证据并通过受控恢复流程更新待执行任务的证据引用。
3. Ozon 调用前的事务再次锁定账号、店铺、仓库、本地状态和精确证据，校验平台 ID、类型和证据摘要没有变化。
4. 商品仍通过现有商品导入接口创建；确认商品导入成功后才更新目标 RFBS 仓库库存。
5. 商品导入成功而库存更新失败时，任务进入现有 `PARTIAL_SUCCESS`/恢复链路，保留 Ozon task ID 和商品成功证据，禁止重新创建商品。

网络读取不在数据库事务中等待；先获取只读结果，再在短事务内用版本、摘要和过期时间进行 CAS/锁定校验。

## API 与页面 contract

仓库公开 DTO 兼容新增：

```json
{
  "listingEligibility": {
    "eligible": false,
    "code": "RFBS_VALIDATION_REQUIRED",
    "fulfillmentType": "RFBS",
    "evidenceRequired": true,
    "validatedAt": null,
    "expiresAt": null
  }
}
```

页面规则：

- FBS 继续显示原有资格结果；
- RFBS 未验证时显示“创建任务时将验证”，而不是误报“暂无仓库”；
- 验证失败时展示安全、可操作的中文提示；
- 选择店铺或仓库变化时清空旧验证状态；
- 按钮 loading、重复点击和迟到响应继续使用现有 generation/intent 边界；
- 前端不能通过伪造 `eligible=true` 绕过后端。

## 失败、恢复与可观测性

稳定失败码至少包括：

- `RFBS_VALIDATION_REQUIRED`；
- `RFBS_WAREHOUSE_NOT_FOUND`；
- `RFBS_WAREHOUSE_DISABLED`；
- `RFBS_WAREHOUSE_SCOPE_MISMATCH`；
- `RFBS_WAREHOUSE_EVIDENCE_EXPIRED`；
- `RFBS_WAREHOUSE_CHANGED`；
- `UNSUPPORTED_FULFILLMENT_TYPE`。

失败分级：

- 认证/归属/类型错误：不可自动重试；
- Ozon 读取超时或 5xx：可重试，但不得创建任务；
- 上传前证据过期：重新只读验证后恢复；
- 商品已创建但库存失败：只重试库存或进入人工恢复，不重提商品导入。

审计记录验证主体、目标账号/店铺/仓库、证据 ID、结果、安全失败码和时间。日志只记录安全摘要与 correlation ID。

## 测试与验收

### 单元与 contract 测试

- FBS 原有允许/拒绝矩阵保持不变；
- RFBS 零商品且成功证据时允许；
- RFBS 缺失、过期、错账号、错店铺、错平台 ID、停用或类型变化时拒绝；
- FBO、FBP 和未知类型仍拒绝；
- 页面只消费后端资格 contract，并正确显示 RFBS 验证状态。

### PostgreSQL 集成测试

- migration 001–059 可在空库完整执行；
- 历史 FBS 任务无需回填且行为不变；
- 证据 append-only、租户边界、任务绑定和账号删除规则生效；
- 并发创建同一幂等任务只产生一个任务和一个有效证据绑定；
- 仓库变化、证据过期和上传事务 CAS 均失败关闭；
- 商品成功/库存失败不会重复生成商品提交。

### 外部调用测试

- 自动测试仅使用受控 fake Ozon transport；
- 断言验证阶段只有仓库列表只读调用；
- 失败路径断言商品导入和库存更新调用次数为零；
- 成功路径断言先导入商品、确认成功后才更新库存；
- 不在 CI 或本地开发验证中调用真实 Ozon 写接口。

### 用户验收

1. 选择“粽子测试”后能看到 `CEL-测试（RFBS）`；
2. 创建任务时出现明确验证进度；
3. 验证通过后任务可以进入正常生成和审核流程；
4. 仓库失效时在 Ozon 写入前停止；
5. 最终真实商品与库存写入验收必须由用户单独授权一个受控 SKU。

## 影响范围

预计涉及：

- 仓库资格 domain contract；
- Ozon 仓库只读验证 port；
- 自动上架 preference、service、repository 和 upload repository；
- PostgreSQL migration 059；
- 自动上架页面的仓库标签、提示和错误映射；
- 对应单元、contract、PostgreSQL 与受控 transport 测试。

不应修改 Ozon 真实商品内容规则、AI 模型能力测试、店铺切换、订单和促销同步。

## 风险与回滚

主要风险是 Ozon 仓库类型或状态字段在不同账号返回形态不一致，以及商品成功后库存更新不接受目标仓库。实现必须对未知字段失败关闭，并通过受控 transport 变体测试覆盖。

代码回滚可撤销 RFBS 资格、验证 port、页面显示和任务绑定逻辑；FBS 路径恢复原行为。migration 059 为 additive：回滚代码后保留证据表和 nullable 引用，不删除审计证据。若以后需要收紧数据库约束，应使用新的 forward-only migration，不直接删除历史数据。

## 未验证范围

- 当前 Ozon 账号对 `CEL-测试` 的最新只读仓库响应形态；
- 当前账号是否允许对该 RFBS 仓库更新库存；
- 真实商品导入、真实库存写入和真实订单履约；
- 生产灾备与生产流量下的外部 API 限流表现。

这些范围必须在实施完成后如实报告，不能用 mock 或旧测试结果替代真实验证。
