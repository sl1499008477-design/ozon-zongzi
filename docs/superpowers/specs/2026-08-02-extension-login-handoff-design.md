# 扩展登录状态即时交接设计

## 业务目标

用户点击扩展的“前往登录”后，系统优先复用同一 Chrome 用户配置中已经打开的 ozon 粽子 Web 页面。即使用户输入账号密码超过现有约 10 秒的自动重试窗口，Web 登录成功后也必须立即主动触发扩展会话交换，不要求用户刷新页面或点击“重新检查”。

## 验收标准

1. 已存在受信 Web 标签页时，“前往登录”只聚焦该标签页，不重复创建页面，也不改写其当前业务路径。
2. 不存在受信 Web 标签页时，新建精确的 Web 登录地址 `http://127.0.0.1:3000/login`。
3. Web 未登录时，扩展仍可做有限的初始请求，但登录花费超过 10 秒不会导致后续永远无法建立会话。
4. Web 账号状态从未登录变为已登录时，Web 端通过同源页面消息发布不含凭据的“认证桥已就绪”信号；扩展内容脚本收到后重新发起一次性票据请求。
5. Web 已登录但扩展会话缺失时，复用标签页后由后台显式发送 `collector.auth.request`，无需刷新 Web 页面。
6. 票据、Web Bearer 和 Collector Token 不写入页面消息、日志或持久化本地存储；现有一次性票据交换和后端权限校验保持不变。
7. 登录失败或票据交换失败时，不伪装为成功；现有“重新检查”仍作为人工恢复入口。

## 方案比较与选择

### 方案 A：无限轮询

内容脚本永久每秒询问一次登录状态。实现简单，但会在每个 Web 标签页持续产生消息，扩展和页面休眠后行为也不稳定，不符合 KISS 与可观测性要求。

### 方案 B：延长固定等待时间

把 10 秒改成 1 分钟或更久。只能降低复现概率，仍无法覆盖用户登录更慢、短信验证或页面后台休眠，不解决根因。

### 方案 C：事件驱动交接（采用）

保留短时初始重试用于已登录页面的快速连接；当 React Web 应用确认账号已登录并安装认证桥时，主动发布无敏感数据的 ready 事件。内容脚本只在该事件或后台明确请求时重新开始一次受限认证周期。该方案没有永久轮询，能覆盖任意登录耗时，并保持现有一次性票据安全边界。

## 组件与职责

### Web 认证桥

`app/src/collector-auth-bridge.js` 继续负责接收合法的同源认证请求、向后端申请一次性票据并返回严格的响应 contract。安装成功后额外发布一次 `collector.auth.ready` 页面事件；事件只包含协议、动作，不含账号、票据或 Token。

### 扩展 Web 内容脚本

`extension/content/sync-auth.js` 继续负责生成请求 ID、校验响应并把一次性票据交给后台兑换。新增对 `collector.auth.ready` 的严格同源监听；收到后清理旧定时器并重置受限请求周期。重复 ready 事件不得并发交换，也不得绕过现有最大交换次数。

### 扩展后台与弹窗

`extension/background/service-worker.js` 的 `openFrontend` 负责查找受信 Web 标签页：存在则聚焦，不存在则创建。聚焦或新建后，以尽力而为方式向页面发送 `collector.auth.request`；页面尚未加载时允许静默等待内容脚本自己的 document-start 流程。

`extension/popup/popup.js` 不再直接无条件 `chrome.tabs.create`，而是调用稳定的 `openFrontend` action。打开失败时在弹窗内展示明确提示，不改变认证状态。

## 数据流

1. 用户点击“前往登录”。
2. 弹窗请求后台打开 Web 登录入口。
3. 后台优先聚焦已有受信 Web 标签页，否则创建登录页。
4. 用户完成 Web 登录，React 状态确认账号存在并安装认证桥。
5. Web 认证桥发布 `collector.auth.ready`。
6. 内容脚本发出带新 request ID 的 `collector.auth.request`。
7. Web 认证桥向后端申请一次性票据并回传。
8. 内容脚本将票据交给扩展后台；后台兑换为账号级 Collector 会话。
9. 用户再次打开扩展时，`getAuth` 直接读取已建立的会话并显示主界面。

## Contract 与安全边界

- 新增页面消息动作：`collector.auth.ready`，沿用 `SONLI_COLLECTOR_AUTH` 协议。
- ready 消息允许字段只有 `protocol` 和 `action`。
- 认证 request/response 的 request ID、同源检查、受信发送方检查保持不变。
- Web Bearer 只由 Web 请求后端票据接口时使用；扩展只接触一次性票据和 Collector 会话。
- 不修改数据库表、账号权限、店铺边界、采集接口或 Seller 登录状态。

## 错误处理

- 找不到现有标签页：新建登录页。
- 聚焦现有标签页失败：回退为新建登录页。
- 页面尚未注入内容脚本：后台发送认证请求失败可忽略，由 document-start 和 ready 事件兜底。
- 后端票据申请失败：Web 不向页面泄露后端错误详情。
- 票据兑换失败：保持未登录，允许 ready 或“重新检查”开始新的受限周期。

## 测试与验证

1. Web bridge 单元测试：安装后发布精确的 ready 消息，且消息不含敏感字段。
2. sync-auth 运行时测试：初始 10 次请求耗尽后，ready 事件能重新发起；重复 ready 不产生并发交换；来源或协议错误的事件被拒绝。
3. 后台路由测试：已有本地/品牌 Web 标签页时复用并聚焦；没有时创建登录页；发送请求失败不导致打开失败。
4. popup 路由测试：按钮调用 `openFrontend`，不再直接新建标签页；失败提示可见。
5. 回归：Collector 会话、portal bridge 安全策略、插件 readiness、ZIP 启动、个人数据扫描和源/发布物一致性全部通过。

## 影响范围与回滚

影响扩展弹窗、service worker、受信 Web 内容脚本、Web 认证桥及其测试；不涉及数据库迁移、真实 Ozon 调用、密钥或生产数据写入。

如出现问题，回滚本功能提交并重新执行扩展打包即可恢复原有固定重试流程；现有 Collector 会话和 Web 登录状态无需迁移或清理。
