# 采集箱类目属性按 Ozon 字典 ID 匹配设计

## 目标

修复采集箱商品编辑页中“类目已匹配、商品类型已有显示值，但仍提示必填”的问题。对于 Ozon 字典型类目属性，来源值与目标店铺字典值即使语言不同，只要 `dictionary_value_id` 相同，就应视为同一个有效选项。

## 已确认的根因

- 商品 `1751027904` 的来源属性 `8229` 为“热水瓶”，并带有 `dictionary_value_id: 92576`。
- 目标店铺类目属性 `8229` 的唯一字典选项显示为 `Термос`。
- 当前页面预填和必填校验只保留、比较显示文字，没有使用来源字典 ID。
- 因为“热水瓶”与 `Термос` 文本不同，选择框可以显示来源文字，但必填校验认定它不是目标字典中的合法选项。

## 方案比较

### 方案 A：字典 ID 优先，文字兜底（采用）

保留来源属性中的字典 ID；构造目标类目输入行时，先用 ID 查找目标字典选项，命中后使用目标选项的正式值。只有来源没有 ID 或目标字典没有相同 ID 时，才沿用现有文字和多语言别名匹配。

优点是符合 Ozon 的稳定标识，语言变化不会影响匹配，改动范围小；风险是必须正确处理单选、多选和缺失 ID。

### 方案 B：继续扩充中俄文字别名

为“热水瓶/Термос”等值增加人工翻译。实现简单，但无法覆盖所有类目和语言，后续仍会反复出现同类问题，因此不采用。

### 方案 C：由后端统一把所有来源属性转换成目标字典值

数据最集中，但会扩大接口 contract 和后端职责，涉及更多页面与回归范围，不符合本次最小修复目标，因此暂不采用。

## 数据流

1. 从采集商品、补全草稿及来源类目证据中读取属性值和 `dictionary_value_id`。
2. 类目匹配完成后，读取目标店铺当前类目的属性和字典选项。
3. 对字典型属性：
   - 优先按字典 ID 查找目标选项；
   - 命中后把控件值规范化为目标选项值，例如将来源“热水瓶/92576”规范化为目标 `Термос/92576`；
   - ID 缺失或无匹配时，使用现有文字、品牌特殊值和多语言别名逻辑；
   - 两种方式都不匹配时继续保持未填写，不能猜测。
4. 必填校验和提交继续使用目标字典选项，不改变上架接口。

## 边界与安全

- 字典 ID 必须属于同一个属性 ID，不能跨属性匹配。
- 只接受当前目标店铺、当前类目返回的字典选项，不能凭来源 ID 伪造目标值。
- 多选属性逐项按 ID 匹配并去重；无法匹配的项不应让整个必填属性被误判为有效。
- 非字典文本和数字属性保持现有行为。
- 不修改数据库结构、后端权限、上架接口或 Ozon 外部调用。

## 验收标准

- 来源 `8229 = 热水瓶, dictionary_value_id = 92576`，目标选项 `Термос, dictionary_value_id = 92576` 时，页面自动选择 `Термос`，不再提示“类目属性「商品类型」”。
- 相同文字但不同字典 ID 时，不能错误按 ID 命中；仍按既有文字兜底规则判断。
- ID 匹配范围严格限制在同一个属性中。
- 没有字典 ID 的旧采集数据仍可使用现有文字匹配。
- 品牌 `Нет бренда`、普通文本属性、多选字典属性和其他必填校验不回归。

## 测试

- 单元回归：验证跨语言同 ID 自动命中、ID 缺失文字兜底、不同 ID 不误命中、多选去重。
- 页面契约：验证商品类型控件得到目标字典正式值，必填缺失列表不再包含商品类型。
- 回归：运行采集箱类目、字典准备、上架准备及 Web 构建检查。

## 回滚

本次不涉及迁移。出现问题时恢复前端字典解析改动和对应测试即可；数据库与已采集商品无需回滚。
